description: Показать сводку по журналу прогонов (задачи, круги ревью, застревания, разрез по типам, динамика)
argument-hint: "[без аргументов]"

Покажи сводку по журналу прогонов проекта.

1. **Запусти скрипт агрегации**: `${CLAUDE_PLUGIN_ROOT}/hooks/scripts/adk-stats.sh`
   (читает `$ADK_LOGS_DIR` либо `.adk/logs/` в корне проекта; схема событий
   журнала, которую скрипт умеет агрегировать, —
   `${CLAUDE_PLUGIN_ROOT}/docs/adr/001-journal-event-schema.md`, документ
   кита, а не текущего проекта).
2. **Покажи вывод как есть** — это детерминированный подсчёт по факту, не
   пересказывай его цифрами из головы; разрез по типам задач (количество,
   средние круги ревью на тип) — тоже как есть. Последний раздел вывода —
   «Расход задач прогонов» (issue #136, SPEC-003 AC-6): распределение
   расхода по event=task записей `autopilot-*.jsonl` — минуты и токены,
   каждая строка как «медиана, p90, максимум» (поля duration/tokens пишет
   adk-ralph.sh, ADR-001 «Расширения схемы»). Раздел появляется только
   когда в журнале есть хотя бы одна запись с расходом; по нему калибруются
   дефолты бюджетов (`policies.autopilot.budget.*`, docs/config.md).
3. **Журнал пуст** (скрипт так и сообщает) — скажи об этом прямо: записей
   ещё нет, сводить нечего; не выдумывай цифры и не подставляй нули как
   значимую статистику. Кроме «пусто», скрипт детерминированно различает
   ещё четыре состояния — «завершённых задач ещё нет, N в работе»,
   «только autopilot-записи без issue-задач» (с расходом прогонов, если
   он записан), «файлы журнала есть, но валидных записей в них нет» и
   полные агрегаты по завершённым задачам — в каждом просто передавай
   текст скрипта как есть.
4. **Кратко интерпретируй** непустой вывод: 2–3 предложения о том, что
   бросается в глаза (высокая доля застреваний, повторяющаяся причина,
   рост/спад кругов ревью по неделям) — без домыслов сверх того, что видно
   в цифрах.
