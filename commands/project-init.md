Инициализируй проект под процесс agent-dev-kit. Шаблоны: `${CLAUDE_PLUGIN_ROOT}/templates/`,
контракт команд описан в `${CLAUDE_PLUGIN_ROOT}/docs/contract.md`.

## Шаги

1. **Осмотрись.** Целевая директория — `$ARGUMENTS` или текущая. Определи:
   проект пустой или существующий, какой стек уже виден (package.json,
   pyproject.toml и т.д.), есть ли git.

2. **Спроси недостающее** одним вопросом через AskUserQuestion:
   - стек (`nextjs` / `nestjs` / `python-service` / другой) — только если не
     очевиден из содержимого;
   - название и одно предложение описания — только если проект пустой.

3. **Пустой проект — сначала каркас стека штатным генератором**, не выдумывай
   структуру сам: `npx create-next-app@latest` / `npx @nestjs/cli new` /
   `uv init`. Флаги подбирай неинтерактивные.

4. **Наложи шаблоны:**
   - `templates/base/CLAUDE.md` → `CLAUDE.md`; заполни все `{{плейсхолдеры}}`
     реальными значениями, секцию «Специфика проекта» — фактами об этом проекте
     (или удали, если добавить нечего);
   - `templates/base/gitignore` → дополни существующий `.gitignore`
     недостающими строками (не затирай его);
   - `templates/<стек>/scripts/*` → `scripts/`, сделай исполняемыми;
   - `templates/<стек>/ci.yml` → `.github/workflows/ci.yml`.
   - `docs/` не создавай заранее — директории появятся с первой спекой/ADR.

5. **Другой стек** (не из шаблонов): возьми ближайший шаблон за образец и
   напиши реализацию контрактных скриптов под инструменты этого стека сам,
   соблюдая семантику из contract.md (check по файлам — быстрый; test с
   пустым набором тестов — не провал; fix молчалив).

6. **Проверь контракт вживую.** `./scripts/check` и `./scripts/test` должны
   реально отработать (поставь dev-зависимости, если генератор их не поставил:
   для node-стеков как минимум typescript, eslint, prettier и тест-раннер).
   Не завершай инициализацию с падающим контрактом — это фундамент всех гейтов.

7. **Git.** Если репозитория нет — `git init -b main` и первый коммит.
   Спроси про GitHub: если нужен remote — предложи `gh repo create`.

8. **Итог пользователю:** что создано; гейты уже активны (проверки после
   каждой правки, тесты перед завершением работы); дальше процесс:
   `/spec` → `/plan` (апрув → issues) → `/work`.
