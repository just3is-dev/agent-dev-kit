argument-hint: "[лимит задач за прогон, по умолчанию 5; опционально номера issues]"
---

Выполни очередь открытых issues текущего milestone в автономном режиме.
Ты — оркестратор: сам код не пишешь, на каждую задачу запускаешь свежего
субагента с чистым контекстом. Работает связка гарантий: субагент может
довести PR до ready единственным путём — через вердикт APPROVE ревьюера;
хук блокирует merge черновиков; значит, мержится только прошедшее ревью.

## Параметры

- Лимит задач за прогон: из `$ARGUMENTS`, по умолчанию 5.
- Если в `$ARGUMENTS` перечислены номера — работай только по ним,
  в указанном порядке (с учётом блокировок).

## Цикл (повторяй, пока не исчерпан лимит и есть доступные задачи)

Перед первой итерацией залогируй старт прогона (схема ADR-001,
docs/adr/001-journal-event-schema.md; журнал — наблюдаемость, не гейт):
`${CLAUDE_PLUGIN_ROOT}/hooks/scripts/adk-log.sh autopilot-$(date
+%Y-%m-%d) event=run_start || true`.

1. **Выбор задачи**: `gh issue list --state open` текущего milestone;
   возьми первый issue без метки `needs-human`, у которого все
   «Blocked by #N» закрыты. Нет доступных — заверши цикл.

2. **Исполнение — субагентом с чистым контекстом.** Прочитай
   `${CLAUDE_PLUGIN_ROOT}/commands/work.md` и передай субагенту
   (general-purpose) его содержимое как инструкции + номер issue +
   путь к проекту. Субагент проходит полный цикл: ветка → tdd → гейты →
   draft-PR → ревью (до двух кругов) → при APPROVE переводит PR в ready.
   В свой контекст не тащи детали его работы — только итог.

3. **Разбор результата** (по фактам из gh, не со слов субагента). После
   каждого решения залогируй итог задачи по схеме ADR-001 (журнал —
   наблюдаемость, не гейт: провал записи не блокирует прогон):
   `${CLAUDE_PLUGIN_ROOT}/hooks/scripts/adk-log.sh autopilot-$(date
   +%Y-%m-%d) event=task issue=<N> result=<merged|stuck|skipped>
   [reason="<причина, только при result=stuck>"] || true` (причина обычно
   содержит пробелы — заключай в кавычки, как `reason` в шаге 7 `/work`).
   - **PR ready** → `gh pr merge <PR> --squash --delete-branch` (squash:
     один issue = один коммит в main, заголовок PR становится сообщением
     коммита); если настроен CI — дождись зелёного перед merge
     (`gh pr checks --watch`); после merge — залогируй `result=merged`,
     следующая итерация. Исключение — `policies.merge` со значением
     `human-review-required` или `human-only`
     (`${CLAUDE_PLUGIN_ROOT}/hooks/scripts/adk-config.sh policies.merge
     agent-after-approve`): merge не выполняй (хук всё равно заблокирует)
     — PR остаётся ready и ждёт человека, это не застревание (метку
     needs-human не ставь, предохранитель не трогай); залогируй
     `result=skipped reason="merge делает человек (policies.merge)"` и
     переходи к следующей итерации;
   - **PR остался draft или PR нет** → задача застряла: поставь метку
     (`gh label create needs-human 2>/dev/null; gh issue edit <N> --add-label
     needs-human`), отправь уведомление
     (`${CLAUDE_PLUGIN_ROOT}/hooks/scripts/notify-send.sh "Autopilot"
     "issue #N застрял: <краткая причина>"`), залогируй `result=stuck
     reason="<краткая причина>"`; задачи, зависящие от неё, пропускай до
     конца прогона — на каждую пропущенную залогируй свою запись
     `result=skipped`.

4. **Предохранитель**: два застревания подряд — остановись полностью,
   даже если лимит не исчерпан: вероятна системная проблема.

## Завершение

Сводка: сделано и смержено / застряло с метками / пропущено по
зависимостям; уведомление notify-send об окончании прогона. Формулировки
сводки — по политике (`${CLAUDE_PLUGIN_ROOT}/hooks/scripts/adk-config.sh
policies.merge agent-after-approve`): при `human-review-required` и
`human-only` merge агенту запрещён (хук блокирует `gh pr merge`), поэтому
ready-PR в сводке — «PR готов к ревью коллеги», не «смержено». Залогируй
итог прогона целиком по схеме ADR-001 (тем же файлом, что и записи по
задачам — `autopilot-<дата>` за сегодня):
`${CLAUDE_PLUGIN_ROOT}/hooks/scripts/adk-log.sh autopilot-$(date
+%Y-%m-%d) event=run_end done=<смержено> stuck=<застряло>
skipped=<пропущено> || true`. Если за прогон смержено ≥3 задач —
напомни про `/consolidate` на границе вехи.

Запрещено: мержить draft (хук всё равно не даст), редактировать issues
кроме метки needs-human, «доделывать» застрявшие задачи самому — их
разбирает человек (обычно через `/review`).
