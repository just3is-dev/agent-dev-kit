---
description: Инвентаризация межзадачного мусора (дубли, дрейф, мёртвый код) → апрув → задачи рефакторинга
argument-hint: "[область: milestone, пакет или путь; по умолчанию — весь проект]"
---

Проведи консолидацию по правилам скилла consolidate. Запускается на
границах вех: после закрытия milestone или крупной группы задач.

1. **Инвентаризация (read-only).** Запусти отдельного агента с чистым
   контекстом **на модели opus** (межзадачный анализ качества — работа с
   максимальным рычагом и редким запуском, экономить на модели нельзя):
   пусть пройдёт по области (`$ARGUMENTS` или весь проект) и
   соберёт кандидатов по категориям скилла consolidate (структурные дубли,
   «одно и то же разными способами», мёртвый код, лишние абстракции,
   хвосты ревью/TODO, дрейф нейминга) в формате кандидата из скилла.
   Обязательно: пройтись и по открытым вердиктам ревьюера в PR
   (`gh pr list --state merged` + комментарии) — несделанные «мелочи»
   это тоже кандидаты. Инвентаризатор ничего не правит.

2. **Покажи пользователю список целиком**, отсортированный
   «польза ↓, риск ↑», с итогом: сколько кандидатов, какие рекомендуешь
   (высокая польза + низкий риск), какие делать не стоит и почему.
   НИЧЕГО не создавай до явного выбора пользователя.

3. **После выбора** — преврати выбранных кандидатов в issues (`gh issue
   create`, milestone текущий или «consolidation»; без GitHub — чекбоксы
   в docs/plans/): каждый issue самодостаточен, в теле — все места
   (file:line), целевое состояние и DoD «поведение не изменилось,
   существующие тесты зелёные без правок». Тривиальную мелочь (< ~20
   строк, риск низкий) можно с согласия пользователя собрать в один
   общий issue «мелкая уборка».

4. **Выполнение** — обычным `/work` по одной задаче: гейты, ревью,
   draft-PR. Правила для исполнителя и ревьюера — в скилле consolidate
   (поведение не меняется, тесты только перемещаются).

5. **Отчитайся**: созданные issues, рекомендованный порядок.
