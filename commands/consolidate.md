---
description: Инвентаризация межзадачного мусора (дубли, дрейф, мёртвый код) → апрув → задачи рефакторинга
argument-hint: "[область: milestone, пакет или путь; по умолчанию — весь проект]"
---

Проведи консолидацию по правилам скилла consolidate. Запускается на
границах вех: после закрытия milestone или крупной группы задач.

1. **Инвентаризация (read-only).** Запусти отдельного агента с чистым
   контекстом **на модели opus** (межзадачный анализ качества — работа с
   максимальным рычагом и редким запуском, экономить на модели нельзя):
   пусть пройдёт по области (`$ARGUMENTS` или весь проект) и
   соберёт кандидатов по категориям скилла consolidate (структурные дубли,
   «одно и то же разными способами», мёртвый код, лишние абстракции,
   хвосты ревью/TODO, дрейф нейминга) в формате кандидата из скилла.
   Обязательно: пройтись и по открытым вердиктам ревьюера в PR
   (`gh pr list --state merged` + комментарии) — несделанные «мелочи»
   это тоже кандидаты. Инвентаризатор ничего не правит.

2. **Петля сбежавших дефектов и выжимка журнала** — перед показом
   кандидатов:
   - Прогони `${CLAUDE_PLUGIN_ROOT}/hooks/scripts/ac-check.sh --complete .`
     (именно версию плагина: `scripts/ac-check` проекта — копия времён
     project-init, старая копия не знает `--complete`): на границе
     милестоуна аннотации «ждёт #N» не оправдывают отсутствие теста —
     каждый AC утверждённых спек обязан быть покрыт. Непокрытые — блокер
     закрытия вехи, не кандидат на потом.
   - Собери баг-issues области по label баг-типа — тип задачи задаётся
     label'ом (SPEC-002), не текстом: прочитай label из конфига
     (`${CLAUDE_PLUGIN_ROOT}/hooks/scripts/adk-config.sh
     types.bug.label type:bug`), затем `gh issue list --state all
     --label <label баг-типа> --limit 200 --json
     number,title,body,milestone` (отфильтровав по `$ARGUMENTS`, если он
     задан как milestone) и вытащи из тела каждого строку
     «Сбежал от: <гейт>». Посчитай агрегацию по гейтам (check / test /
     reviewer / процесс): сколько дефектов сбежало от каждого. Если
     баг-issues с label не нашлось (или нет GitHub) — прямо скажи
     «данных нет, распределение не считается» и не выдумывай
     гейт-кандидат на усиление. Иначе покажи распределение и
     самый частый («текущий») гейт с конкретным предложением усиления
     (новый паттерн теста, правило ревьюера, пункт скилла) — это
     отдельная рекомендация, не кандидат из шага 1.
   - Сформируй выжимку журнала прогонов: вызови
     `${CLAUDE_PLUGIN_ROOT}/hooks/scripts/adk-stats.sh` (агрегаты по
     `.adk/logs/` — задачи, круги ревью, застревания; пустой журнал —
     скажи прямо, не подставляй нули как значимую статистику, см.
     `/stats`) и предложи закоммитить результат одним файлом
     `docs/observability/<веха>.md` (веха — milestone или дата границы).
     Сам журнал (`.adk/logs/`) не коммитится — в git попадает только эта
     агрегированная выжимка, и только по явному согласию пользователя.

3. **Покажи пользователю список целиком**, отсортированный
   «польза ↓, риск ↑», с итогом: сколько кандидатов, какие рекомендуешь
   (высокая польза + низкий риск), какие делать не стоит и почему.
   Вместе со списком — распределение «Сбежал от» по гейтам и выжимка
   журнала из шага 2. НИЧЕГО не создавай и не фиксируй до явного выбора
   пользователя.

4. **После выбора** — преврати выбранных кандидатов в issues (`gh issue
   create`, milestone текущий или «consolidation»; без GitHub — чекбоксы
   в docs/plans/): каждый issue самодостаточен, в теле — все места
   (file:line), целевое состояние и DoD «поведение не изменилось,
   существующие тесты зелёные без правок». Тривиальную мелочь (< ~20
   строк, риск низкий) можно с согласия пользователя собрать в один
   общий issue «мелкая уборка». Если пользователь согласился закоммитить
   выжимку журнала — один коммит с файлом `docs/observability/<веха>.md`.

5. **Выполнение** — обычным `/work` по одной задаче: гейты, ревью,
   draft-PR. Правила для исполнителя и ревьюера — в скилле consolidate
   (поведение не меняется, тесты только перемещаются).

6. **Отчитайся**: созданные issues, рекомендованный порядок, усиленный
   гейт (если предложен), закоммичена ли выжимка журнала.
