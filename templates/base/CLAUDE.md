## Процесс

- Фича начинается со спеки в `docs/specs/` (команда `/spec`), задачи — issues
  в GitHub (команда `/plan`), выполнение — `/work`.
- Одна задача = одна ветка = один PR. В main напрямую не коммитим.
- Неочевидные технические решения фиксируются в `docs/adr/`.
- Документы самодостаточны: читаются без других документов и истории чата.

## Данные и миграции

- Изменения схемы БД — только через миграции; правки схемы мимо них запрещены.
- Каждая миграция имеет откат (down) либо явную пометку в самой миграции,
  почему откат невозможен.
- Тесты поднимают схему из миграций на чистой БД — схема в коде и в
  миграциях не могут разойтись незаметно.
- Миграции, удаляющие или преобразующие данные, — отдельный PR с явным
  предупреждением в описании.
