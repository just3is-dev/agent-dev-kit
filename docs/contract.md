# Контракт команд проекта

Каждый проект, работающий с agent-dev-kit, обязан иметь три исполняемых скрипта.
Хуки плагина зовут их вслепую, не зная стека проекта. Реализация скриптов —
дело проекта (генерируется при инициализации из шаблона под выбранный стек).

| Скрипт | Аргументы | Что делает | Требования |
|---|---|---|---|
| `scripts/check` | `[файлы...]` | Статические проверки: типы + линт | Без аргументов — весь проект, плюс AC-трассируемость (см. ниже). С аргументами — только затронутая область, быстро (цель < 30 сек), без AC-трассируемости. Exit ≠ 0 при любой ошибке, ошибки — в stdout/stderr. |
| `scripts/test` | — | Все тесты проекта | Exit ≠ 0 при провале. Вывод должен показывать, какие тесты упали. Для сервисов сюда же входит smoke «приложение стартует» (bootstrap на фейках с немедленным выходом): тест-раннеры транспилируют код сами и не ловят ошибки рантайм-сборки — резолв модулей, ESM/CJS, DI. |
| `scripts/fix` | `[файлы...]` | Автоформат и авто-исправимый линт | Молча правит файлы. Exit ≠ 0 только если исправить невозможно. |

## Правила

- Скрипты должны работать из корня проекта без предварительной настройки
  окружения (сами активируют venv, зовут npx и т.п.).
- В монорепе скрипт сам определяет по путям файлов, какие пакеты затронуты,
  и запускает проверки только для них. Готовый корневой диспетчер —
  `templates/monorepo/`: пакетом считается любая поддиректория со своим
  `scripts/check`, новые пакеты подхватываются автоматически.
- Добавил в проект новый язык/сервис — обязан расширить реализацию скриптов,
  чтобы контракт покрывал и его. Код вне контракта = непроверяемый код.
- Полный прогон `scripts/check` (без аргументов) вызывает `scripts/ac-check .`
  хвостом, если этот хелпер исполняем: он падает, если у какого-то AC
  approved-спеки нет ни одного помеченного теста. Исключение — переходное
  состояние милестоуна: критерий с аннотацией `(ждёт #N)` сразу после
  токена («AC-7 (ждёт #52)»: тест запланирован в issue #N; ставит `/plan`,
  снимает PR, добавляющий тег-тест) принимается без теста. Полнота без
  скидок проверяется на границе милестоуна: `ac-check --complete`
  (вызывает `/consolidate`) требует тест для каждого AC, игнорируя
  аннотации. Хелпер копируется
  project-init'ом из плагина (`hooks/scripts/ac-check.sh` →
  `scripts/ac-check`); отсутствие хелпера ничего не ломает. Кастомный
  стек (шаг 7 `/project-init`) обязан вызывать его так же.
  Обновление копии: инициализация копирует хелпер один раз, обновления
  плагина в уже инициализированные проекты сами не долетают. Путь
  обновления — повторный запуск `/project-init` в корне проекта (шаг 5
  команды): он безусловно перезаписывает `scripts/ac-check` свежей версией
  из плагина. Пример: проект инициализирован до issue #54, его копия
  `scripts/ac-check` не понимает аннотацию «ждёт #N» — approved-спека с
  аннотированным AC даёт там красный `scripts/check` (громко, не
  ложно-зелёно) до обновления копии; повторный `/project-init` подтягивает
  свежий хелпер, и `scripts/check` снова корректно учитывает аннотацию.
- Скрипты — единственная точка входа: CI зовёт те же `scripts/check` и
  `scripts/test`, что и хуки. Локальные гейты и CI не могут разойтись.

## Как контракт используют хуки плагина

- `PostToolUse` (после каждого Edit/Write): `scripts/check <файл>`.
  Ошибки возвращаются агенту, он обязан их исправить.
- `Stop` (агент завершает работу): `scripts/test`, если в рабочем дереве
  есть изменения. Провал теста не даёт завершить работу.

Если скриптов в проекте нет, хуки молча пропускают проверки — плагин
безопасно установлен глобально и не мешает посторонним репозиториям.
