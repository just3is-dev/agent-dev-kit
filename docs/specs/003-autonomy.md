# SPEC-003: Автономия

Статус: approved

## Зачем

`/autopilot` прожёвывает очередь только внутри живой интерактивной сессии:
человек держит терминал открытым, следит за ходом и перезапускает прогон
после лимита задач. При трёх параллельных проектах надзор за исполнением
утверждённой очереди — самое дорогое место процесса, хотя решений человека
в нём уже нет: спека и план утверждены, дальше механика. Нужен автономный
цикл, который выполняет все доступные issues без открытой сессии и без
человека рядом — с механическими предохранителями вместо надзора:
жёсткими бюджетами, многоуровневым breaker'ом и честной сводкой по итогам.

## Что делаем

### Ralph-цикл: внешний скрипт, свежий процесс на задачу

`adk-ralph.sh` — bash-скрипт кита, запускаемый вручную из корня проекта.
Цикл: выбрать следующий доступный issue (открытый, без `needs-human`, с
закрытыми блокерами) → выполнить его **свежим headless-процессом**
(`claude -p` с инструкциями `/work`) → разобрать результат по фактам gh
(как `/autopilot`: ready-PR → merge, иначе застревание) → следующая
итерация. Памятью между итерациями служат git, issues и журнал `.adk/` —
не контекст модели: контекст каждой задачи чист, итерация воспроизводима,
падение процесса не убивает прогон.

Цикл останавливается сам, в любом из четырёх случаев:
- **очередь пуста** — доступных issues не осталось (расписание «запускать
  каждую ночь» сознательно не делаем — см. Границы);
- **бюджет прогона исчерпан** — чистая остановка: текущая задача
  доводится до вердикта, следующая не берётся;
- **сработал breaker** (см. ниже);
- **стоп-файл**: `touch .adk/stop` — цикл дочитывает текущую итерацию и
  выходит; файл удаляется при следующем старте.

### Жёсткие бюджеты

Конфиг (`adk.config.json`, блок `policies.autopilot.budget`):
- `task`: `maxMinutes`, `maxTokens` — на одну задачу. Превышение =
  застревание: метка `needs-human`, запись в журнал, breaker считает.
- `run`: `maxMinutes`, `maxTokens` — на прогон целиком. Превышение =
  чистая остановка цикла.
- `sizeLargeMultiplier` — множитель для задач с label `size:large`
  (ставит планировщик при декомпозиции, когда задача заметно крупнее
  типовой). Категория вместо точной цифры: планировщик хорошо отличает
  крупное от обычного и плохо угадывает числа.

Бюджеты жёсткие: превышение всегда останавливает, «мягких предупреждений»
нет. Фактический расход (минуты и токены из usage headless-процесса)
пишется в журнал по задаче — `/stats` показывает распределение, и дефолты
конфига калибруются фактикой, а не ощущениями.

### Стадийный circuit breaker

Три уровня вместо нынешнего бинарного «2 застревания подряд → стоп»;
пороги — в конфиге (`policies.autopilot.breaker`):

- **Задача** (реакция: `needs-human`, skip, цикл продолжается):
  2 круга ревью без APPROVE; бюджет задачи превышен; гейты не позволили
  довести PR до ready.
- **Прогон** (реакция: остановка цикла + уведомление): `maxStuckPerRun`
  застреваний за прогон (дефолт 2 — консервативно, как сейчас);
  доля пропущенных из-за зависимостей задач выше `maxSkippedShare`.
- **Система** (реакция: немедленный полный стоп, новые итерации
  запрещены): гейты красные на main до старта итерации; ошибка самих
  хуков или журнала; серия git-конфликтов при актуализации подряд.

Ложный стоп стоит одну команду перезапуска; ложное продолжение — ночь
мусорных PR. Дефолтные пороги выбираются консервативно.

### Изоляция v1: пермишены, не OS-sandbox

Headless-процессы запускаются с минимальным allowlist разрешений проекта
(`.claude/settings.json`), **без** `--dangerously-skip-permissions`.
Защита в глубину остаётся той же, что в интерактивном режиме: хуки-гейты,
секрет-скан, draft-PR-механика, серверная защита main. Полная OS-изоляция
(профиль `sandbox-exec`: запись только в корень проекта и tmp, сеть только
до api.anthropic.com и github.com) описывается в документации как задел
будущей опции `policies.autopilot.sandbox`, но в v1 не реализуется:
она не должна блокировать остальную автономию.

### Сводка прогона и HITL

Итог каждого прогона — сводка: сделано/смержено, застряло (с причинами),
пропущено, расход времени и токенов по задачам, причина остановки. Сводка
выводится в терминал, пишется в журнал (`event=run_end` расширяется) и
дублируется локальным уведомлением (`notify-send.sh`).

Человек переходит из петли над петлю только на исполнении утверждённой
очереди. **Ворота спеки и плана не делегируются никогда**: ralph работает
только по issues, созданным из утверждённого плана; ни спеку, ни план, ни
конфиг он не меняет. Каждое делегирование исполнения (merge без человека
и т.п.) — явный атрибут конфига с историей в git (принцип SPEC-002).

## Границы

- Никакого расписания (cron/launchd, «каждую ночь в 3:00») — цикл
  запускается человеком и работает до исчерпания очереди. Надстройка с
  расписанием возможна позже поверх того же скрипта.
- Одна задача за раз: никакой параллельности задач и веток — отдельная
  будущая спека.
- Уведомления только локальные (notify-send); канал до телефона — при
  переезде прогонов на удалённую машину, не сейчас.
- OS-sandbox не реализуется (только документируется как задел).
- Ворота спеки и плана не меняются; `/spec`, `/plan`, `/review`,
  `/consolidate` этой спекой не затрагиваются.
- Оценка бюджета per-issue в числах (не категориями) — не делаем:
  планировщик угадывает числа плохо, категории `size:large` достаточно.

## Критерии приёмки

- [ ] AC-1: `adk-ralph.sh` выполняет доступные issues по одному свежим
      headless-процессом и останавливается сам, когда доступных issues
      не осталось; итог — сводка с перечнем сделанного и причиной
      остановки (фикстурная проверка со стабом claude/gh).
- [ ] AC-2: `touch .adk/stop` останавливает цикл после текущей итерации;
      стоп-файл удаляется при следующем старте; причина остановки в
      сводке — «стоп-файл».
- [ ] AC-3: превышение бюджета задачи (время или токены) помечает её
      `needs-human`, логируется и не останавливает цикл; превышение
      бюджета прогона останавливает цикл чисто (текущая задача доведена
      до вердикта, новая не начата).
- [ ] AC-4: задача с label `size:large` получает бюджет задачи,
      умноженный на `sizeLargeMultiplier` из конфига; без label —
      дефолтный.
- [ ] AC-5: breaker уровня прогона: `maxStuckPerRun` застреваний
      останавливают цикл с уведомлением; breaker уровня системы: красные
      гейты main до старта итерации запрещают итерацию немедленно.
- [ ] AC-6: журнал содержит фактический расход (минуты, токены) по
      каждой задаче прогона; `/stats` выводит распределение расхода.
- [ ] AC-7: ralph запускает headless-процессы без
      `--dangerously-skip-permissions`; требуемый allowlist разрешений
      задокументирован; будущая опция OS-sandbox описана в документации
      как задел (без реализации).
- [ ] AC-8: конфиг без блока `budget`/`breaker` (и проект вовсе без
      конфига) работает на консервативных дефолтах из docs/config.md —
      поведение `/autopilot` в интерактивной сессии не меняется этой
      спекой.

## Переходные состояния

Новые гейты этой спеки — бюджеты и breaker — включаются на проекте, где
журнал пуст и фактики для калибровки нет. Первый прогон работает на
консервативных дефолтах из docs/config.md: они могут остановить цикл
раньше времени, и это принятое направление отказа (перезапуск дешевле
ночи мусорных PR); после первых прогонов дефолты калибруются по `/stats`.
Существующие проекты без конфига получают дефолты, их интерактивный
`/autopilot` не меняет поведения (AC-8) — деградаций на легальных
состояниях нет.

## Открытые вопросы

- Конкретные числа консервативных дефолтов (`maxMinutes`/`maxTokens` на
  задачу и прогон, `maxStuckPerRun`, `maxSkippedShare`) — стартовые
  значения предложит план по фактике текущего журнала, калибровка после
  первых прогонов.
