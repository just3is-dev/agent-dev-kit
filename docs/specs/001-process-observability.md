# SPEC-001: Наблюдаемость процесса

Статус: draft

## Зачем

Кит принимает решения о своём развитии вслепую: неизвестно, какие типы
задач застревают, сколько кругов ревью типично, какой гейт чаще всего
пропускает дефекты. Наращивать автономию (ночные прогоны, параллельность)
без наблюдаемости — значит узнавать о проблемах по счёту за токены.
Первая волна развития — «глаза»: журнал, трассируемость критериев,
петля сбежавших дефектов.

## Что делаем

**Журнал прогонов.**
- Каждая завершённая задача (`/work`, `/review`, циклы `/autopilot`)
  оставляет в журнале проекта одну запись: номер issue, число кругов
  ревью, вердикты, итог (смержено / застряло + причина), длительность,
  размер диффа.
- Прогон `/autopilot` дополнительно фиксирует итог прогона целиком.
- Команда сводки показывает агрегаты по журналу: сколько задач, средние
  круги ревью, застревания с причинами, динамика по времени.

**Трассируемость «критерий → тест».**
- Критерии приёмки в спеках нумеруются (`AC-1`, `AC-2`, …).
- Тесты, закрывающие критерий, помечаются его номером (в имени
  describe/it — конвенция фиксируется в скилле tdd).
- Контрактная проверка падает, если у какого-то AC утверждённой спеки
  нет ни одного помеченного теста; ревьюер проверяет, что соответствие
  осмысленно, а не формально.
- Промпты `/spec`, `/plan`, `/work`, reviewer обновлены под конвенцию.

**Петля сбежавших дефектов.**
- Правило процесса: баг-issue содержит строку «Сбежал от: <гейт>» —
  какой гейт обязан был поймать дефект до человека.
- `/consolidate` агрегирует распределение по гейтам и предлагает
  усиление самого «текущего».

## Границы

- Никаких ночных прогонов, расписаний и параллельности — это следующая
  спека («Автономия»), ей нужен журнал из этой.
- Без учёта токенов/стоимости: у хуков и команд нет доступа к биллингу.
- Журнал локален проекту; централизованной аналитики по проектам нет.
- Существующие проекты (shorts-factory) конвенцию AC получают только
  для новых спек — старые спеки задним числом не перенумеровываются.

## Критерии приёмки

- [ ] AC-1: после завершения `/work` в журнале проекта появляется запись
      с issue, числом кругов, вердиктами, итогом и длительностью.
- [ ] AC-2: прогон `/autopilot` оставляет запись на каждую задачу и
      итоговую запись прогона (сделано/застряло/пропущено).
- [ ] AC-3: команда сводки по журналу выводит агрегаты: всего задач,
      средние круги ревью, доля застреваний и их причины.
- [ ] AC-4: контрактная проверка в проекте с конвенцией падает при AC
      без помеченного теста и проходит при полном покрытии (проверено
      фикстурами в тестах кита).
- [ ] AC-5: промпты spec/plan/work/reviewer и скилл tdd содержат правила
      нумерации AC и тегирования тестов.
- [ ] AC-6: правило «Сбежал от: <гейт>» зафиксировано в процессе
      (README + /consolidate агрегирует распределение).

## Открытые вопросы

- Формат и место журнала: предложение — JSONL-файл в служебной папке
  проекта (коммитится, чтобы переживал машины); решает исполнитель с ADR.
