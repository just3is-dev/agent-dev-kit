# ADR-002: общий хелпер `hooks/scripts/lib/paths.sh` — частичная унификация

Дата: 2026-08-07
Статус: accepted <!-- accepted | superseded by ADR-XXX -->

## Контекст

Issue #23 (найдена при `/consolidate`, кандидат K3): `adk-log.sh` и
`adk-stats.sh` дублировали построчно блок определения корня проекта
(`$CLAUDE_PROJECT_DIR`, иначе `git rev-parse --show-toplevel`, иначе
`$PWD`) и каталога журнала (`$ADK_LOGS_DIR` либо `<root>/.adk/logs`).
Отдельно `stop-test.sh` и `notification.sh` дублировали резолв пути к
`notify-send.sh` (`"$(cd "$(dirname "$0")" && pwd)/notify-send.sh"`), но
используют более простое правило корня — `${CLAUDE_PROJECT_DIR:-$PWD}`,
без git-фолбэка.

Задача — консолидация: наблюдаемое поведение не должно меняться (см.
skills/consolidate/SKILL.md, «железное правило» №1). Полная унификация
правила корня — то есть перевод `stop-test.sh`/`notification.sh` на
`adk_project_root()` с git-фолбэком — само по себе поведение бы
изменила: сейчас, если `CLAUDE_PROJECT_DIR` не задан, а cwd — не корень
проекта, `stop-test.sh` использует `$PWD` (тесты искались бы не там, где
раньше), `notification.sh` — тоже. Issue #23 явно оставляет этот выбор на
усмотрение исполнителя, с условием, что DoD (тесты зелёные без правки
ассертов, поведение `adk-log.sh`/`adk-stats.sh` не меняется) должен
выполняться.

## Решение

Частичная консолидация:

- `hooks/scripts/lib/paths.sh` — новый общий хелпер с двумя функциями:
  `adk_project_root()` (правило `adk-log.sh`/`adk-stats.sh`: git-фолбэк) и
  `adk_logs_dir <root>` (правило `$ADK_LOGS_DIR` либо `<root>/.adk/logs`,
  без побочных эффектов — создание `.adk/.gitignore` остаётся в
  `adk-log.sh`, так как это его отличие от `adk-stats.sh`).
  `adk-log.sh` и `adk-stats.sh` подключают хелпер и используют обе
  функции — их наблюдаемое поведение не меняется, дубль убран.
- `adk_notify_send()` — тот же файл, третья функция: резолвит и вызывает
  `notify-send.sh` рядом со скриптом-вызывающим (`$0` внутри функции —
  это `$0` вызывающего скрипта, bash не подменяет его при вызове функции
  из sourced-файла, поэтому путь разрешается так же, как раньше).
  `stop-test.sh` и `notification.sh` подключают хелпер и используют
  только `adk_notify_send()` — их правило определения корня
  (`${CLAUDE_PROJECT_DIR:-$PWD}`, без git-фолбэка) оставлено как есть.

Отклонённая альтернатива: перевести все четыре скрипта на единое правило
корня через `adk_project_root()`. Отклонено — меняет наблюдаемое
поведение `stop-test.sh`/`notification.sh` в сценарии «`CLAUDE_PROJECT_DIR`
не задан, cwd не корень проекта» (начали бы находить корень через git
там, где раньше брали `$PWD`), а это уже не консолидация, а отдельная
задача с собственным DoD и обоснованием пользы (в реальной эксплуатации
`CLAUDE_PROJECT_DIR` всегда задан хуками Claude Code, поэтому у изменения
нет доказанной практической пользы, только риск).

## Последствия

- В `hooks/scripts/lib/` теперь два хелпера: `json-field.sh` (issue #22) и
  `paths.sh` (issue #23) — оба подключаются одинаково,
  `. "$(cd "$(dirname "$0")" && pwd)/lib/<файл>.sh"`, в начале скрипта.
  Новые хук-скрипты должны следовать этой же схеме, а не копировать логику
  инлайн.
- Правило корня проекта в репозитории осталось раздвоенным
  (`adk-log.sh`/`adk-stats.sh` — с git-фолбэком, `stop-test.sh`/
  `notification.sh` — без) — это осознанно, не забытый дубль. Будущая
  консолидация не должна заново предлагать «унифицировать» это без
  отдельного обоснования пользы, перекрывающего риск смены поведения.
- Если `stop-test.sh`/`notification.sh` понадобится git-фолбэк по
  причине, отличной от «унификации ради унификации» (например, реальный
  баг с `CLAUDE_PROJECT_DIR` не заданным вне хуков), это отдельная задача
  через спеку/план, не консолидация.
