# ADR-021: Хелпер версии плагина ищет `plugin.json` self-location'ом, не `find ~/.claude`

Дата: 2026-09-30
Статус: accepted <!-- accepted | superseded by ADR-XXX -->

## Контекст

Issue #154 (SPEC-004 AC-5) просит писать версию плагина в `event=run_start`
журнала (`adk-ralph.sh` и `/autopilot`), чтобы разбор инцидента знал, на
какой версии кита шёл прогон. Нужен один хелпер (ADR-002: общее — в
`hooks/scripts/lib/`), не разбор `plugin.json` в двух местах.

Развилка: кит — сам себе плагин (этот репозиторий догфудится), поэтому
`.claude-plugin/plugin.json` лежит то ли в корне самого кита (когда
`adk-ralph.sh` запущен вручную из этого репозитория — штатный режим,
шапка файла), то ли в установленном кэше плагина потребительского
проекта (где `plugin.json` самого проекта не существует вовсе — это файл
кита, не потребителя). Готовый прецедент той же развилки — `ac-check.sh`
(`docs/contract.md`): сама копия в потребительском проекте
(`scripts/ac-check`) физически покинула дерево плагина и не способна
определить своё расположение относительно `plugin.json` вообще —
поэтому обновление копии делает не сама копия, а отдельная документированная
команда (`docs/contract.md:47`), которая ищет исходник плагина через
`find ~/.claude -path '*agent-dev-kit*/hooks/scripts/ac-check.sh'`
(ищет сам `ac-check.sh`, не `.claude-plugin/plugin.json` — версию копии
`docs/contract.md` сверяет не по `plugin.json`, а прямым `diff` с
найденным исходником).

## Решение

**Self-location по `${BASH_SOURCE[0]}` самого хелпера, с override через
`$CLAUDE_PLUGIN_ROOT`, если он задан как реальная переменная окружения.**
`hooks/scripts/lib/plugin-version.sh` всегда остаётся частью дерева
плагина (в отличие от `ac-check.sh` — он никуда не копируется): в
рантайме этот файл лежит по пути `<корень плагина>/hooks/scripts/lib/
plugin-version.sh`, то есть ровно тремя каталогами ниже корня — что в
самом ките при догфудинге (где корень плагина = корень репозитория), что
в установленном кэше потребителя (где корень плагина = корень кэша).
`adk_plugin_root` поэтому просто поднимается на три каталога от
собственного `${BASH_SOURCE[0]}`:

```sh
(cd "$(dirname "${BASH_SOURCE[0]}")/../../.." && pwd)
```

Ветка `$CLAUDE_PLUGIN_ROOT` — не резолв markdown-синтаксиса (`${CLAUDE_PLUGIN_ROOT}`
текстом внутри `*.sh` не резолвится нигде, кроме markdown-инструкций
команд Claude Code — это отдельный, не связанный механизм), а проверка
уже существующей в `adk-ralph.sh` переменной окружения: сам
`adk-ralph.sh` выставляет и экспортирует `CLAUDE_PLUGIN_ROOT` для
дочернего headless-процесса `claude -p` (нужно ему для резолва markdown в
`commands/work.md`), и хуки Claude Code получают `CLAUDE_PLUGIN_ROOT` как
реальную переменную окружения своего процесса. Override нужен на случай,
когда self-location и фактический источник исполнения расходятся (вызов
из-под другого `CLAUDE_PLUGIN_ROOT`, тесты, эмулирующие потребительский
кэш) — тот же принцип приоритета, что уже применяет `adk-ralph.sh` для
собственного `plugin_root` (`${CLAUDE_PLUGIN_ROOT:-$(cd "$SCRIPT_DIR/../.."
&& pwd)}`).

Отклонённая альтернатива: **`find ~/.claude -path
'*agent-dev-kit*/.claude-plugin/plugin.json'` (по образцу приёма
`docs/contract.md` для обновления копии `ac-check.sh`)**. Отклонено —
этот приём существует специально для файла, покинувшего дерево плагина
(копия в потребительском репозитории); `lib/plugin-version.sh` никогда
не копируется, сорсится на месте, и self-location для него строго
точнее: `find` по `~/.claude` рискует найти чужую или множественную
установку кита (несколько версий в разных маркетплейсах), а
self-location всегда указывает ровно на тот экземпляр плагина, который
сейчас исполняется.

Отклонённая альтернатива: **читать `plugin.json` через `adk_project_root()`**
(корень проекта, `lib/paths.sh`). Отклонено — верно только для
догфудинга (где корень проекта совпадает с корнем плагина); в
потребительском проекте `adk_project_root()` вернул бы корень проекта
потребителя, где `.claude-plugin/plugin.json` не существует вообще.

## Последствия

- `hooks/scripts/lib/plugin-version.sh` (`adk_plugin_version`,
  `adk_plugin_root`) — единственное место разбора `plugin.json` ради
  версии; `adk-ralph.sh` (`event=run_start`) и `/autopilot` (шаг «Перед
  первой итерацией», через CLI-обёртку `adk-plugin-version.sh`) читают
  версию только через него.
- Будущий читатель `plugin.json` ради других полей (не только `version`)
  переиспользует `adk_plugin_root`, а не копирует резолв корня заново.
- Если когда-нибудь появится второй хелпер, который, как `ac-check.sh`,
  копируется из дерева плагина в проект потребителя, — ему нужен
  `find`-приём `ac-check.sh`, а не self-location: это решение относится
  только к файлам, остающимся внутри дерева плагина.
