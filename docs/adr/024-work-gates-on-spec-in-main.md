# ADR-024: `/work` не берёт issue, пока файл его спеки не в main

Дата: 2026-09-30
Статус: accepted <!-- accepted | superseded by ADR-XXX -->

## Контекст

ADR-009 заставляет `/plan` мержить PR спеки финальным шагом (после
создания issues вехи), через тот же хук `bash-guard.sh`, что и любой
`gh pr merge`. При `policies.merge=agent-after-approve` (дефолт) это
проходит внутри одного прогона `/plan`. При `human-review-required` или
`human-only` хук отказывает агенту: PR спеки остаётся ready, а issues
вехи (с аннотациями `AC-N (ждёт #M)`) уже созданы и видны в GitHub. `/work`
может взять такой issue немедленно — но шаг 3 предписывает снять
аннотацию «ждёт #N» в том же PR, где появился тест, а файла спеки в
`main` ещё нет: снимать аннотацию не с чего (issue #218).

Это не гипотетическое окно: пресет «командный» (`docs/config.md`) держит
`policies.autopilot.enabled=true` вместе с `policies.merge=
human-review-required` — `/autopilot` и `hooks/scripts/adk-ralph.sh` в
этой конфигурации штатно продолжают выбирать задачи, пока PR спеки ждёт
человека.

## Решение

`/work` шаг 1 читает из тела issue литеральную строку `Спека:
docs/specs/NNN-<слаг>.md` (её пишет `/plan` шаг 4 — формат теперь
зафиксирован текстом, не только «ссылкой» смыслом) и проверяет файл в
default branch (`git cat-file -e origin/<default>:<путь>`, нотация
`<default>` — ADR-023; изначально здесь стоял буквальный
`origin/main`, issue #249). Файла нет — issue не берётся: при
авто-выборе пропускается тем же способом, что незакрытая
«Blocked by #N»; номер задан явно — остановка с объяснением пользователю.
`/autopilot` шаг 1 получает симметричную проверку в своей собственной
(текстовой) логике выбора задачи — без неё оркестратор передал бы такой
issue субагенту, тот остановился бы без ветки и PR, а шаг 3 `/autopilot`
(судит по фактам `gh`: PR нет) ошибочно пометил бы это как застревание
(`needs-human`, уведомление) вместо легального ожидания человека.

`hooks/scripts/adk-ralph.sh` получает симметричную проверку тем же
способом, что уже применён к `owner:human` (issue #158): новая функция
`spec_missing(it)` в Python-селекторе `select_next` ищет в теле issue ту
же строку «Спека: …», и если извлечённый путь отсутствует среди файлов
`docs/specs/*.md` в `origin/$default_branch` — issue молча исключается из
кандидатов (не NEXT, не BLOCKED_ON_READY), без needs-human, без записи в
журнал, вне счётчиков `skipped`/`stuck` (`$default_branch` — та же
переменная, что ADR-007 §6/issue #144, вычисляется один раз до цикла; круг
2 ревью PR #246 исправил здесь хардкод `origin/main`, который на
репозитории с другим default branch молча и навсегда исключал бы каждый
issue со спекой). Список файлов `origin/$default_branch` обновляется перед
каждым вызовом `select_next` (`git fetch origin` + `git ls-tree`) — дёшево
и подхватывает merge спеки человеком посреди прогона. Круг 1 ревью PR #246
отклонил первоначальный план оставить `adk-ralph.sh` нетронутым: без этой
проверки ralph отдал бы такой issue `claude -p` с текстом `commands/work.md`,
тот остановился бы без ветки и PR (новый шаг 1 `/work`, «номер задан явно —
остановись»), а `find_pr_state` прочёл бы «PR нет» как застревание —
детерминированная ложная `needs-human` на каждом прогоне в пресете
«командный», пока PR спеки ждёт человека: регрессия относительно
поведения до этого PR (раньше ralph просто доводил задачу до ready-PR,
не зная о контракте — единственной ценой была «осиротевшая» аннотация,
которую теперь ловит гейт ADR-020).

Отклонённые альтернативы:
- **Вариант (а) issue #218** — `/work` при отсутствии файла спеки в main
  сам правит её в ветке спеки. Отклонено пользователем: решение принято
  до реализации как вариант (б), не предмет выбора агента.
- **Вариант (в) issue #218** — переносить снятие аннотации на первый PR
  после merge спеки, с механической проверкой (issue #200 смежен).
  Отклонено: не устраняет саму гонку — issue вехи всё равно можно начать
  раньше, чем спека в main, просто аннотация снимется позже; вариант (б)
  устраняет гонку в корне, не давая issue стартовать вовсе.
- Оставить `hooks/scripts/adk-ralph.sh` нетронутым, отложив фикс отдельным
  issue, — первоначальный план этого ADR. Отклонено кругом 1 ревью PR #246:
  объём оказался сопоставим с уже существующим классом исключения
  `owner:human` (одна функция, две точки вызова, одна фикстура), а не
  отдельным механизмом с каскадами — цена отсрочки (детерминированная
  ложная `needs-human`, объяснено выше) перевесила экономию на PR.

## Последствия

- Формат ссылки на спеку в теле issue — теперь часть контракта, а не
  просто «для человека»: `/plan` обязан писать строку `Спека: …` с
  буквальным путём, `/work`, `/autopilot` и `adk-ralph.sh` — парсить её.
  Issue, созданный не через `/plan` (вручную, без строки «Спека:»),
  проверке не подлежит — она не может звонить в пустоту.
- Проверка read-only и дешёвая (`git fetch` + `git cat-file -e` /
  `git ls-tree`) — не требует изменений в `hooks/scripts/adk-config.sh`
  или конфиге проекта.
- `hooks/scripts/adk-ralph.sh` теперь делает один дополнительный
  `git fetch origin` перед каждым `select_next` — лишний сетевой вызов на
  итерацию цикла, даже когда ни один issue очереди не ссылается на спеку;
  отказ fetch (сеть) не роняет прогон (`|| true`), лишь оставляет список
  файлов default branch устаревшим на эту итерацию — безопасное направление
  отказа (issue со спекой остаётся вне кандидатов, не получает ложную
  `needs-human`).
- Круг 2 ревью PR #246: распознавание строки «Спека: …» в
  `hooks/scripts/adk-ralph.sh` ищет литерал «Спека:» и путь
  `docs/specs/….md` независимо друг от друга в одной строке, не требуя
  привязки к позиции между ними — буквальная реализация контракта `/plan`
  шага 4 («путь присутствует буквальным текстом строки», без ограничений
  на обрамление). Жёсткая привязка к позиции в первой версии распознавала
  только одну из легальных форм (markdown-ссылка с путём сразу в
  квадратных скобках) и молча не находила путь в остальных (бэктики,
  `**жирный**` префикс, `[SPEC-NNN: путь](url)`) — issue с такой формой
  проезжал бы как обычный кандидат, даже если его спека реально не в
  default branch.
- Issue, чьё тело просто цитирует шаблон критерия приёмки дословно
  («Спека: docs/specs/NNN-<слаг>.md», буквально с плейсхолдерами `NNN` и
  `<слаг>») — не ссылка на реальный файл, а пример формата. `spec_missing()`
  извлечёт путь `docs/specs/NNN-<слаг>.md`, он никогда не появится в
  `origin/$default_branch` (это не валидное имя файла спеки), и такой issue
  навсегда считается «спека не в main» — не NEXT, не needs-human, вне
  журнала. Источник — issue не через `/plan`, скопировавший формулировку
  критерия приёмки как есть; `/plan` шаг 4 сам пишет реальный путь, не
  плейсхолдер.
