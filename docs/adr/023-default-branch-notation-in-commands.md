# ADR-023: нотация `<default>` в текстах команд вместо буквального `origin/main`

Дата: 2026-10-02
Статус: accepted <!-- accepted | superseded by ADR-XXX -->

## Контекст

`commands/*.md` исполняет LLM-оркестратор дословно, не bash. Тексты
`/work`, `/review`, `/plan`, `/autopilot` писали `origin/main` буквально
(проверка спеки вехи, счёт отставания ветки, rebase/merge при
актуализации). На репозитории с default branch, отличным от `main`
(например `trunk`), оркестратор сверял бы работу не с той веткой.
`hooks/scripts/adk-ralph.sh` эту проблему уже решил переменной
`$default_branch` (ADR-007 §6, issue #144/#220, ADR-021); тексты команд
остались позади (issue #249, найдено в круге 3 ревью PR #246).

## Решение

Рецепт определения default branch описан **один раз** — в нотации
`commands/work.md` рядом с `<N>` и `<PR>`: `<default>` — сперва `git
symbolic-ref --short refs/remotes/origin/HEAD` (срезать префикс
`origin/`), затем `gh repo view --json defaultBranchRef -q
.defaultBranchRef.name`, затем `main`. Тот же порядок, что в
`adk-ralph.sh`. Во всех остальных местах (`work.md` шаги 1 и 6,
`review.md` шаг 5, `plan.md` шаг 5, `autopilot.md` шаг 3) стоит
`origin/<default>`; `review`/`plan`/`autopilot` отсылают к нотации
`/work` фразой «определение — в нотации `/work`». Это тот же приём
«канон в одном месте, остальные ссылаются», что у рецепта актуализации
ветки (шаг 6 `/work`).

Отклонено: вписывать трёхшаговый рецепт в каждое из пяти мест. Дублирует
команды, и при правке рецепта (например, ещё один запасной путь) часть
копий осталась бы старой — именно так появился разрыв с `adk-ralph.sh`.

## Последствия

- Для репозитория с default branch `main` поведение не меняется:
  `<default>` разворачивается в `main`, а запасной вариант — тоже `main`.
- Doc-тесты `tests/run.sh` (issue #249) закрепляют: в `commands/*.md` нет
  буквального `origin/main`; рецепт (`symbolic-ref`) встречается ровно в
  одном месте; остальные команды отсылают к нотации `/work`.
- Прозаические упоминания «main» без `origin/` (конфликт с main,
  `git checkout main && git pull` в шаге 2 `/work`, `git diff main...` в
  шаге 7) этим решением не затронуты; в `commands/` остаются как отдельный
  хвост того же класса.
