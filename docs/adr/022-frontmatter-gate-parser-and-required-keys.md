# ADR-022: гейт фронтматтера — минимальный парсер, не strict YAML

Дата: 2026-09-30
Статус: accepted <!-- accepted | superseded by ADR-XXX -->

## Контекст

Issue #201: блокер круга 2 PR #199 — перевёрстка сломала фронтматтер
`commands/stats.md` (строка-продолжение потеряла отступ и встала на
колонку 0), команда теряла `description`/`argument-hint` в рантайме
Claude Code, а ни `scripts/check`, ни тесты кита этого не увидели. Нужен
локальный гейт, парсящий фронтматтер `commands/*.md`, `agents/*.md`,
`skills/*/SKILL.md` и проверяющий обязательные по типу ключи.

Ревью PR #199 также отметило, что `commands/autopilot.md` и
`commands/work.md` не проходят «строгий YAML»: их `description` содержит
`: ` (двоеточие+пробел) внутри обычного русского текста («...в работу:
ветка → тесты...», «...очередь issues: свежий субагент...»), не в
кавычках — для strict-YAML парсера (PyYAML и подобных) это неоднозначно
с вложенным mapping и отвергается с ошибкой вида «mapping values are not
allowed here».

Обе команды тем не менее исполняются рантаймом Claude Code как есть, без
правки — значит рантайм терпимее строгого YAML. Разбор механизма (по
наблюдаемому поведению и эмуляции fallback-логики на библиотеке `yaml`,
без доступа к исходному коду самого бинаря рантайма) даёт следующую
картину в три шага:

1. Рантайм пробует строгий YAML-парсер. Если фронтматтер — валидный
   YAML, разбор на этом заканчивается.
2. При ошибке строгого парсера рантайм запускает построчный fallback:
   каждая **отдельная физическая строка** (независимо от остальных, без
   учёта того, что она может быть частью многострочной записи)
   проверяется регэкспом вида `^ключ:\s+значение$`; если строка подходит
   и в значении есть символ, из-за которого спотыкается строгий YAML
   (двоеточие, и другие спецсимволы вне данного гейта), эта конкретная
   строка кавотируется (`ключ: "значение"`) и YAML парсится заново.
3. Если и после построчного кавотирования документ не разбирается —
   фронтматтер целиком схлопывается в `{}`: все ключи теряются, не
   только проблемный.

Из шага 2 следует важная граница, уточнённая по сравнению с первой
версией этого ADR: fallback кавотирует **строку**, а не **запись**, и
делает это по регэкспу вида `^ключ:\s+значение$` — триггером служит
`: ` (двоеточие с пробелом) где угодно внутри значения **или** двоеточие
на самом конце строки (эквивалент «после двоеточия — граница строки»,
та же позиция, что и пробел, с точки зрения этого регэкспа). Строка вида
`ключ:значение` (двоеточие без пробела после) под регэксп вообще не
попадает — не кавотируется и не спасается, даже если сама по себе была
бы однострочной записью.

Однострочная запись (`description: ...` без последующего продолжения) —
строка и запись совпадают: если значение содержит триггер, кавотирование
спасает её целиком, поэтому `autopilot.md`/`work.md` работают. Но если у
записи есть строка-продолжение (отступная строка ниже), а первая строка
содержит триггер (`: ` где угодно в значении ИЛИ двоеточие на самом
конце строки) — квотирование первой строки само по себе сработает (она
реально станет валидным кавотированным скаляром), а вот осмысленного
места для уже имеющейся под ней отступной строки не остаётся: законченный
кавотированный скаляр не может «принять» более ничего снизу, и построчный
разбор такого сочетания проваливается («all collection items must start
at the same column» / «nested mappings are not allowed in compact
mappings» — конкретная формулировка зависит от того, что именно идёт в
отступной строке). Та же строка-продолжение, если триггер — внутри неё
самой, никогда не кавотируется в принципе (регэксп привязан к началу
строки через `^ключ:`, а продолжение начинается с отступа, не с
идентификатора ключа) — она ломает разбор без всякого шанса на починку.
В обоих случаях результат один: документ не собирается и схлопывается
в `{}`, а не теряется только значение одного ключа. Поэтому триггер
(`: ` или двоеточие на конце строки) губит многострочную запись, где бы
он ни был — в первой строке записи или в строке-продолжении. Конкретные
тексты ошибок парсера в примерах выше — из эмуляции на библиотеке `yaml`
(см. начало «Контекста»), не из стек-трейса самого бинаря рантайма.

## Решение

1. **Парсер — минимальный «key: value / отступ-продолжение», не strict
   YAML, с границей терпимости, повторяющей рантайм ровно там, где
   рантайм её проводит.** Каждая строка с колонки 0 вида
   `key: остаток_строки` задаёт ключ; значение — весь остаток строки
   после первого `:`. Отступная строка — продолжение значения
   предыдущего ключа. Гейт отвергает как потенциальную потерю
   фронтматтера рантаймом:
   - строку-продолжение, в которой есть триггер `: ` или она сама
     заканчивается на `:` (построчный fallback её не кавотирует — она
     не строка вида `ключ: значение`, а индикатор триггера по сути тот
     же, что и у первой строки ниже — функция `has_colon_trigger` в
     `frontmatter-check.sh` общая для обеих проверок);
   - первую строку записи с тем же триггером (`: ` где угодно в
     значении или `:` на самом конце строки), если у записи есть хотя
     бы одна строка-продолжение (fallback кавотирует эту строку саму по
     себе, но висящая отступная строка ниже всё равно ломает разбор —
     граница из «Контекста»); однострочная запись с тем же триггером
     (без продолжения) не отвергается — именно эту форму рантайм
     спасает;
   - `key:value` без пробела после `:` (fallback требует `:\s+`).
   Строка-продолжение, потерявшая отступ и вставшая на колонку 0 (сам
   класс бага PR #199), синтаксически неотличима от новой пары
   «ключ: значение» — если у неё к тому же есть `:`, она не заводится
   молча как новый ключ, а отвергается белым списком допустимых ключей
   типа файла (`ALLOWED`): неизвестный ключ — ошибка. Реализация —
   `hooks/scripts/frontmatter-check.sh` (bash-обвязка над инлайн
   `python3 -c`, стиль кита — `hooks/scripts/lib/json-field.sh`). Без
   внешней зависимости: `yaml` не входит в stdlib python3, а
   `pip install pyyaml` в контракте кита ничем не обеспечен и не нужен
   ради одной этой проверки (issue #201 явно предлагает такую
   альтернативу).
2. **`commands/autopilot.md` и `commands/work.md` не правятся.** Их
   `description` — однострочные значения с двоеточием как знаком
   препинания, и рантайм их уже спасает построчным fallback (см.
   «Контекст»). Альтернатива — заквотить значение под strict YAML
   (`description: "..."`) — отклонена: она требует квотить произвольный
   русский текст всякий раз, когда в нём появляется двоеточие, что
   регулярно (описания команд — свободная проза), хрупко к следующей
   правке формулировки и не даёт защиты от реального класса бага
   (потерянный отступ строки-продолжения) — тот класс минимальный
   парсер ловит без всякого квотирования.
3. **Обязательные ключи — по типу файла, не общий список.**
   `commands/*.md`: `description`, `argument-hint`. `agents/*.md`:
   `name`, `description`, `model`, `tools`. `skills/*/SKILL.md`: `name`,
   `description`. Список — из issue #201, зафиксирован константой
   `REQUIRED` в `frontmatter-check.sh` (тот же набор, что и `ALLOWED`,
   пока в ките нет опциональных ключей); пустое значение — включая
   пустую строку в двойных или одинарных кавычках (`""`/`''`) — снимается
   перед проверкой и считается отсутствующим, не только отсутствующий
   ключ.
4. **Повторяющийся ключ — предупреждение, не ошибка.** Рантайм на
   дублирующихся ключах теряет документ целиком («map keys must be
   unique»), гейт на этом же случае — не теряет: второе присваивание
   молча перезаписывает первое в своей внутренней структуре данных, и
   только печатает предупреждение в stderr с номером строки и именем
   ключа, не крася check. Это осознанно более мягкая реакция, чем у
   рантайма, а не повторение его границы: дубль ключа не возникает из
   перевёрстки описания (не тот класс риска, что #201), встречается
   редко и обычно заметен на ревью невооружённым глазом — красить им
   check означало бы плодить блокеры на случай вне исходной мотивации
   этой задачи. Зафиксировано явным исключением в «Последствиях».

## Последствия

- Гейт ловит класс бага PR #199 (сломанный отступ строки-продолжения —
  как без двоеточия в перенесённой строке, так и с ним через белый
  список ключей) и формы потери фронтматтера рантаймом из-за `:`,
  описанные в «Контексте»: триггер (`: ` где угодно в значении или `:`
  на самом конце строки) в строке-продолжении, тот же триггер в первой
  строке многострочной записи, отсутствие пробела после `:`.
- Гейт не эквивалентен строгому YAML: однострочное значение с `:` в
  тексте не считается ошибкой (сознательный выбор п. 2, граница —
  построчный fallback рантайма для записи ровно в одну физическую
  строку), а то же самое в многострочной записи — считается, потому что
  рантайм там теряет весь документ.
- Гейт **терпимее** рантайма ровно в одном явном, осознанном месте —
  повторяющийся ключ (п. 4): рантайм теряет документ целиком, гейт даёт
  предупреждение и остаётся зелёным. Это не пробел, а намеренное
  решение по соотношению цена/риск для класса, не связанного с мотивацией
  issue #201.
- Гейт не покрывает весь алфавит YAML-спецсимволов, из-за которых может
  спотыкаться строгий парсер (`# { } [ ] * & | > % @` и обратная кавычка)
  и буквальный таб как отступ строки-продолжения — вне рамок issue #201:
  ни один файл кита сегодня их не использует, а строгая проверка по
  всему этому алфавиту — другая, более широкая задача (настоящая
  YAML-совместимость), не локальный гейт от перевёрстки описания. Если
  появится файл с такими символами или понадобится точное повторение
  всей границы рантайма — нужен отдельный ADR/issue, не молчаливое
  расширение этого гейта. Если когда-нибудь понадобится настоящая
  YAML-семантика (списки, вложенные структуры во фронтматтере) целиком —
  этот ADR устареет, нужен новый с `supersedes ADR-022`.
- Список обязательных/допустимых ключей — плоские константы в скрипте;
  расширение на новый тип файла, новый обязательный ключ или появление
  первого опционального ключа (`REQUIRED` ≠ `ALLOWED`) правит
  `REQUIRED`/`ALLOWED` и покрывающие тесты в одном месте, без отдельного
  конфига.
