# ADR-021: гейт фронтматтера — минимальный парсер, не strict YAML

Дата: 2026-09-30
Статус: accepted <!-- accepted | superseded by ADR-XXX -->

## Контекст

Issue #201: блокер круга 2 PR #199 — перевёрстка сломала фронтматтер
`commands/stats.md` (строка продолжения с колонки 0), команда теряла
`description`/`argument-hint`, а ни `scripts/check`, ни тесты кита этого
не увидели. Нужен локальный гейт, парсящий фронтматтер `commands/*.md`,
`agents/*.md`, `skills/*/SKILL.md` и проверяющий обязательные по типу
ключи.

Ревью PR #199 также отметило, что `commands/autopilot.md` и
`commands/work.md` не проходят «строгий YAML». Проверено PyYAML: оба
файла падают с `mapping values are not allowed here` — их `description`
содержит `: ` (двоеточие+пробел) внутри обычного русского текста
(«...в работу: ветка → тесты...», «...очередь issues: свежий
субагент...»), не в кавычках. По спецификации YAML это неоднозначно с
вложенным mapping, поэтому strict-YAML парсер (PyYAML и подобные) такой
plain scalar отвергает.

Ревью круга 1 PR #243 разобрало, чем на самом деле спасаются эти два
файла в рантайме Claude Code (бинарь 2.1.114): рантайм сначала пробует
строгий YAML (Bun.YAML); при провале — построчный fallback, который
кавычит **только однострочные** записи вида `^ключ:\s+значение$`, чьё
значение содержит спецсимвол (включая `: `), и парсит заново; если и
это не спасает — фронтматтер целиком схлопывается в `{}` (все ключи
теряются). `autopilot.md`/`work.md` попадают под этот fallback именно
потому, что их `description` — одна физическая строка. Многострочное
значение, чья строка-продолжение сама содержит `: `, под построчный
fallback не попадает («nested mappings are not allowed in compact
mappings») и теряется целиком — то есть терпимость рантайма к «:» уже
кончается на границе «одна физическая строка», а не «весь фронтматтер».

## Решение

1. **Парсер — минимальный «key: value / отступ-продолжение», не
   strict YAML, с границей терпимости, повторяющей рантайм.** Каждая
   строка с колонки 0 вида `key: остаток_строки` задаёт ключ; значение —
   весь остаток строки после первого `:`, включая любые дальнейшие `:` в
   тексте (терпимо к «двоеточию в значении» ровно там же, где терпим
   построчный fallback рантайма: в пределах одной физической строки).
   Отступная строка — продолжение предыдущего значения, но сама не
   имеет права содержать `: ` — рантайм на таком значении падает
   («nested mappings are not allowed in compact mappings»), гейт обязан
   падать тоже, а не быть мягче. Строка не с колонки 0, но и не
   отступная (сам класс бага PR #199 — потерянный отступ), —
   синтаксическая ошибка; если при этом у неё есть `:`, она обязана
   входить в белый список допустимых ключей типа файла (`ALLOWED`) —
   иначе она бы молча заводила несуществующий ключ вместо того, чтобы
   быть распознанной как та же потерянная строка-продолжение (найдено
   ревью круга 1 PR #243: `issues: свежий субагент` на колонке 0 без
   белого списка проходил бы как новый ключ `issues`, обрезая
   `description`). Реализация — `hooks/scripts/frontmatter-check.sh`
   (bash-обвязка над инлайн `python3 -c`, стиль кита —
   `hooks/scripts/lib/json-field.sh`). Без внешней зависимости: `yaml`
   не входит в stdlib python3, а `pip install pyyaml` в контракте кита
   ничем не обеспечен и не нужен ради одной этой проверки (issue #201
   явно предлагает такую альтернативу).
2. **`commands/autopilot.md` и `commands/work.md` не правятся.** Их
   `description` — однострочные значения с двоеточием как знаком
   препинания, и рантайм их уже спасает построчным fallback (см.
   «Контекст»). Альтернатива — заквотить значение под strict YAML
   (`description: "..."`) — отклонена: она требует квотить произвольный
   русский текст всякий раз, когда в нём появляется двоеточие, что
   регулярно (описания команд — свободная проза), хрупко к следующей
   правке формулировки и не даёт защиты от реального класса бага
   (потерянный отступ строки продолжения) — тот класс минимальный
   парсер ловит без всякого квотирования, фиксацией «`key:` только с
   колонки 0» и белым списком ключей (п. 1).
3. **Обязательные ключи — по типу файла, не общий список.**
   `commands/*.md`: `description`, `argument-hint`. `agents/*.md`:
   `name`, `description`, `model`, `tools`. `skills/*/SKILL.md`: `name`,
   `description`. Список — из issue #201, зафиксирован константой
   `REQUIRED` в `frontmatter-check.sh` (тот же набор, что и `ALLOWED`,
   пока в ките нет опциональных ключей); пустое значение — включая
   пустую квотированную строку `""`, кавычки снимаются перед проверкой
   (найдено ревью круга 1 PR #243) — считается отсутствующим, не только
   отсутствующий ключ.

## Последствия

- Гейт ловит класс бага PR #199 (сломанный отступ строки-продолжения —
  как без двоеточия в перенесённой строке, так и с ним, через белый
  список ключей; многострочное значение с `: ` в продолжении;
  пропавший или пустой обязательный ключ) для всех текущих и будущих
  `commands/*.md`, `agents/*.md`, `skills/*/SKILL.md` — без ложных
  срабатываний на естественный текст с двоеточием в пределах одной
  строки.
- Гейт не эквивалентен строгому YAML, но и не терпимее реального
  рантайма Claude Code: значение с несколькими `:` в одной физической
  строке не считается ошибкой (сознательный выбор п. 2, граница —
  построчный fallback рантайма), а то же самое в строке-продолжении —
  считается, потому что рантайм там теряет значение целиком. Если
  когда-нибудь понадобится настоящая YAML-семантика (списки, вложенные
  структуры в фронтматтере) — этот ADR устареет, нужен новый с
  `supersedes ADR-021`.
- Список обязательных/допустимых ключей — плоские константы в скрипте;
  расширение на новый тип файла, новый обязательный ключ или появление
  первого опционального ключа (`REQUIRED` ≠ `ALLOWED`) правит
  `REQUIRED`/`ALLOWED` и покрывающие тесты в одном месте, без отдельного
  конфига.
