# ADR-021: гейт фронтматтера — минимальный парсер, не strict YAML

Дата: 2026-09-30
Статус: accepted <!-- accepted | superseded by ADR-XXX -->

## Контекст

Issue #201: блокер круга 2 PR #199 — перевёрстка сломала фронтматтер
`commands/stats.md` (строка продолжения с колонки 0), команда теряла
`description`/`argument-hint`, а ни `scripts/check`, ни тесты кита этого
не увидели. Нужен локальный гейт, парсящий фронтматтер `commands/*.md`,
`agents/*.md`, `skills/*/SKILL.md` и проверяющий обязательные по типу
ключи.

Ревью PR #199 также отметило, что `commands/autopilot.md` и
`commands/work.md` не проходят «строгий YAML». Проверено PyYAML: оба
файла падают с `mapping values are not allowed here` — их `description`
содержит `: ` (двоеточие+пробел) внутри обычного русского текста
(«...в работу: ветка → тесты...», «...очередь issues: свежий
субагент...»), не в кавычках. По спецификации YAML это неоднозначно с
вложенным mapping, поэтому strict-YAML парсер (PyYAML и подобные) такой
plain scalar отвергает.

## Решение

1. **Парсер — минимальный «key: value / отступ-продолжение», не
   strict YAML.** Каждая строка с колонки 0 вида `key: остаток_строки`
   задаёт ключ; значение — весь остаток строки после первого `:`,
   включая любые дальнейшие `:` в тексте (никакого запрета на «двоеточие
   в значении», в отличие от YAML). Отступная строка — продолжение
   предыдущего значения. Строка не с колонки 0, но и не отступная (сам
   класс бага PR #199 — потерянный отступ), — синтаксическая ошибка.
   Реализация — `hooks/scripts/frontmatter-check.sh` (bash-обвязка над
   инлайн `python3 -c`, стиль кита — `hooks/scripts/lib/json-field.sh`).
   Без внешней зависимости: `yaml` не входит в stdlib python3, а
   `pip install pyyaml` в контракте кита ничем не обеспечен и не нужен
   ради одной этой проверки (issue #201 явно предлагает такую
   альтернативу).
2. **`commands/autopilot.md` и `commands/work.md` не правятся.** Их
   `description` не содержат осмысленного вложенного mapping — это
   обычный текст с двоеточием как знаком препинания. Альтернатива —
   заквотить значение под strict YAML (`description: "..."`) — отклонена:
   она требует квотить произвольный русский текст всякий раз, когда в
   нём появляется двоеточие, что регулярно (описания команд — свободная
   проза), хрупко к следующей правке формулировки и не даёт защиты от
   реального класса бага (потерянный отступ строки продолжения) — тот
   класс минимальный парсер ловит без всякого квотирования, ровно
   благодаря фиксации «`key:` только с колонки 0».
3. **Обязательные ключи — по типу файла, не общий список.**
   `commands/*.md`: `description`, `argument-hint`. `agents/*.md`:
   `name`, `description`, `model`, `tools`. `skills/*/SKILL.md`: `name`,
   `description`. Список — из issue #201, зафиксирован константой
   `REQUIRED` в `frontmatter-check.sh`; пустое значение (после `strip()`)
   считается отсутствующим, не только отсутствующий ключ.

## Последствия

- Гейт ловит класс бага PR #199 (сломанный отступ строки-продолжения,
  пропавший обязательный ключ) для всех текущих и будущих
  `commands/*.md`, `agents/*.md`, `skills/*/SKILL.md` — без ложных
  срабатываний на естественный текст с двоеточием.
- Гейт не эквивалентен строгому YAML: значение с несколькими `:` в
  строке не считается ошибкой (сознательный выбор п. 2), и Claude Code
  рантайм-парсер фронтматтера команд/агентов на практике устроен так же
  терпимо (иначе `autopilot.md`/`work.md` не работали бы как команды до
  этой задачи). Если когда-нибудь понадобится настоящая YAML-семантика
  (списки, вложенные структуры в фронтматтере) — этот ADR устареет,
  нужен новый с `supersedes ADR-021`.
- Список обязательных ключей — плоская константа в скрипте; расширение
  на новый тип файла или новый обязательный ключ правит
  `REQUIRED` и покрывающие тесты в одном месте, без отдельного конфига.
