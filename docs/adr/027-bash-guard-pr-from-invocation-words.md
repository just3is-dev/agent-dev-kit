# ADR-027: bash-guard берёт PR из слов вызова `gh pr merge`, а не регулярками по тексту

Дата: 2026-10-11
Статус: accepted <!-- accepted | superseded by ADR-XXX -->

## Контекст

После ADR-026 хук знает, что команда вызывает `gh pr merge`, но PR, чей
статус проверять, по-прежнему выбирал отдельно: `adk_command_pr_number` —
регулярка `gh +pr +merge +[0-9]+` по всему тексту (только форма «merge,
пробел, номер»), `adk_command_repo_flag` — первый `-R`/`--repo` из любого
места текста. Не извлёкся номер — `gh pr view` без номера, то есть статус PR
**текущей ветки** (issue #266). Дыры, подтверждённые запуском с заглушкой
`gh`: `merge --squash 5`, `merge --squash --delete-branch 5`, `merge 7 &&
merge 5` проходили хук при ready-PR текущей ветки и draft-PR #5; номер из
значения флага (`--subject 7`), URL и имя ветки как селектор не читались.
Все фикстуры хука задавали состояние через `ADK_GUARD_PR_STATE`, который
перекрывает чтение статуса, — выбор PR не проверялся ни одним тестом.

## Решение

Один механизм: лексер из ADR-026 отдаёт не только факт вызова, но и
**слова найденного вызова**; цель каждого вызова извлекается из них по
белому списку флагов `gh pr merge` (`gh pr merge --help`, gh 2.96).

- Флаги без значения: `--admin --auto -d/--delete-branch --disable-auto
  -m/--merge -r/--rebase -s/--squash -h/--help` (короткие склеиваются: `-sd`).
  Флаги со значением (значение — следующее слово или `=…`/склейка у короткого):
  `-t/--subject -b/--body -F/--body-file --match-head-commit
  -A/--author-email -R/--repo`. Значение флага никогда не селектор.
- Первое позиционное слово — селектор (номер, `#N`, URL, ветка, `owner:ветка`;
  допустимые символы ограничены: `$`, подстановка, пробелы — нет). Позиционного
  нет — PR текущей ветки (семантика gh), но только если перед `gh` стоят
  `VAR=значение`, `env`, `command`, `sudo`, `time` или ничего: через другую
  обёртку (`xargs`, `eval`) селектор может прийти снаружи.
- `-R`/`--repo` берётся из слов того же вызова, в любом месте (в том числе до
  `pr`, где gh его сам не принимает).
- Любое отклонение — неизвестный флаг, `--`, флаг без значения, второй
  позиционный, второй `-R`, слово до `merge`, не являющееся флагом,
  недопустимый символ в селекторе или `-R` — запись «не определён» (`?`).
- Перенаправления (`>`, `>>`, `>|`, `<`, `<>`, `&>`, `N>&M`, `<<`, `<<<`)
  лексер выделяет сам: оператор и слово-цель (тело heredoc, строка
  here-string) не попадают в слова вызова и не бывают селектором;
  `merge 7 --squash 2>&1 | tail -5` читается как `merge 7 --squash`. Номер
  дескриптора лексер не разбирает: bash и zsh читают цифры вплотную к `&>`
  по-разному (`5&>f`). Слово из ASCII-цифр вплотную к оператору (`5>f`,
  `5&>f`, `'5'>f`, `12>f`) — после определённого селектора это
  перенаправление (`merge 7 2>&1`), иначе (первое позиционное или значение
  флага) — `?`; при `merge --squash 2>&1` без селектора тоже `?`. Пропуск
  склеенного слова после селектора безопасен: если оболочка читает его как
  слово, у gh два позиционных аргумента и он отказывается (`MaximumNArgs(1)`,
  «accepts at most 1 arg(s), received 2»); если как дескриптор — argv
  совпадает с тем, что видит хук. Слово с `$'…\…'` (ANSI-C не
  декодируется) читается как динамическое; слово с `\r`, `\v`, `\f`,
  прочими управляющими символами и нестандартными пробелами в позиции
  флага или селектора — `?`; `\r` лексер не считает пробелом (как bash), в
  том числе в разделителе heredoc.
- В команде проверяется **каждый** найденный вызов. Фраза в слове команды вне
  белого списка (`bash -c "…"`, `eval`, `| sh`) рядом с найденным вызовом
  добавляет запись `?`: спрятанный второй вызов нельзя проверить, а не
  стоит игнорировать.
- Запись `?` (как и упоминание рядом с неинертной командой, и сбой разбора) —
  отказ с отдельным текстом «не удалось определить, какой PR мержится»; к
  PR текущей ветки это не откатывается. Тексты отказов для определённого
  вызова (черновик, статус не прочитан, `policies.merge`) не меняются.
  `ADK_GUARD_PR_STATE`/`ADK_GUARD_PR_REVIEW_DECISION` по-прежнему перекрывают
  чтение статуса целиком (тестовый обход).

**Контракт хелпера.** `adk_command_invokes_pr_merge` сохраняет коды возврата
(0 — вызов или сбой разбора, 1 — нет вызова, 2 — упоминание) и дополнительно
выставляет глобальную `ADK_PR_MERGE_TARGETS`: по записи `<селектор>|<-R>` на
вызов, одна на строку, `?` — не определён. Выбор «глобальная переменная»,
а не вывод в stdout: функция вызывается без подоболочки (код возврата
нужен в том же процессе), а вывод пришлось бы разбирать вместе с кодом.
Существующие тесты хелпера и хука (`tests/run.sh`, блок issue #260 и
строки политик merge) не менялись. С ADR-028 (issue #265) python-источник
лексера лежит в общей переменной `ADK_INVOCATION_PY` и обслуживает ещё и
`adk_command_git_bypass` (режим `git`): правила разбора слов, перенаправлений
(`Redir`, `Glued`) и белый список `inert()` общие, merge-режим не менялся.

## Отклонено

- **Допатчить регулярку** (`merge( +-[^ ]+)* +[0-9]+`). Каждая форма флагов,
  кавычек, URL и второй вызов — новая дыра; это тот же рукописный парсер по
  тексту, что ADR-026 отверг.
- **Брать первый «похожий на номер» токен после merge.** Значение флага
  (`--subject 7`, `--body "fix 7"`) читается как номер.
- **Разобрать позиционный по любым словам, неизвестный флаг пропускать.**
  Тогда значение неизвестного флага станет селектором; whitelist отказывает.
- **При неопределённом селекторе проверять PR текущей ветки.** Это и есть
  исходная дыра.

## Последствия

- `gh pr merge "$PR" --squash` и `$(…)` вместо номера теперь отказ: номер в
  команде пишется литерально, как делают `/autopilot` и `/work`.
- Редкие ложные отказы: `gh pr list --search merge`, `gh pr checkout merge`
  (слово `merge` после `pr`; детектор вызова из ADR-026 и так их считает
  вызовом). `grep -n gh pr merge f` без кавычек читается как селектор `f`.
  Тот же отказ: вызов внутри `bash -c "…"`/`eval "…"`, обёртки без
  селектора вне списка (`nohup`, `nice`, `timeout`, `sudo -u`, `time -p`,
  `env -u`). Новые относительно ADR-026 ложные отказы из-за правила про
  цифры вплотную к оператору: `merge --squash 2>&1` и `merge --squash
  --delete-branch 2>/dev/null` без селектора, `2>/dev/null gh pr merge
  --squash`, `gh 5>f pr merge 7`, `merge 7 ٥>f`.
- Известные пропуски (проходили и до этого, правила для них нет):
  `GH_REPO=o/r gh pr merge 5` (хук смотрит #5 локального репозитория);
  `xargs -I 7 gh pr merge 7` (плейсхолдер как селектор); команда с
  несколькими вызовами и разными `cd` проверяется по одному git-корню.
- `adk_command_pr_number`/`adk_command_repo_flag` остались только у
  `pr-title-check.sh` (`gh pr create|edit`, fail-open); там та же регулярка
  по тексту — отдельная, менее критичная задача.
- Фикстуры (`tests/run.sh`, блок issue #266) идут с заглушкой `gh` в PATH без
  `ADK_GUARD_PR_STATE`, различающей вызовы с селектором и без, и журналом
  запросов; мутации «номер только в форме merge N» и «проверять только
  первый вызов», «значения флагов не пропускаются», «неизвестный флаг
  игнорируется», «перенаправление — позиционный», «`&>` не оператор»,
  «цифры вплотную к оператору допускаются как селектор», «`$'…\…'`
  допускается», «управляющий символ не неоднозначность», «gh без
  `</dev/null`», «фильтр перенаправлений в `inert()` снят», «`<<`/`<<<`
  не помечают склеенное слово» (фикстуры `7<<<x`, `7<<EOF`), «якорь конца
  строки в `ASCII_DIGITS` снят» (фикстура `7 5a>f`) красят их на копии.
  Таблица в конце блока (`команда => вид => журнал запросов`, вид — черновик /
  не определён / ready / не вызов, причина отказа и журнал сверяются на
  каждой строке) закрепляет перебор по спискам: каждый булев флаг перед и
  после селектора (мутации «флаг со значением» и «убран»: `--admin`, `-s`,
  `--merge`, `--rebase`, `--disable-auto`, `-h`, `--help` и остальные), каждый
  флаг со значением (в том числе `-F`: `-F 7 --squash` запрашивает PR текущей
  ветки, а не 7), каждый вид селектора (`#N`, `owner:ветка`, URL, ветка,
  число: мутации «→ `?`» и «откат на PR текущей ветки»), `-R` в каждой
  позиции (до `pr`, между `pr` и `merge`, до и после селектора, `--repo=`,
  `-Ro/r`, `-sRo/r`, `-sR o/r`: «не передаётся» и «→ `?`») и каждый оператор
  перенаправления вплотную к цифре (`>`, `>>`, `>|`, `>&`, `<`, `<>`, `<&`,
  `&>`, `&>>`, `<<<`: «не помечает склеенное слово»).
