# ADR-028: bash-guard решает про `git commit` / `git push` по вызову и по инертности команды, а не по подстроке

Дата: 2026-10-12
Статус: accepted <!-- accepted | superseded by ADR-XXX -->

## Контекст

`bash-guard.sh` искал два обхода гейтов подстрокой по всему тексту команды:
`git commit` + `--no-verify` и `git push … (--force|-f)` + `(origin|upstream)
 +(main|master)`. Обе стороны подстроки дырявы (issue #265, прогон на main):
`git commit -n -m x`, `-m x -n`, `-nm x`, `-a -n`, `git push origin +main`,
`git push origin HEAD:main --force`, `git push --no-verify origin foo`
проходили, а `echo 'git commit --no-verify'` и `grep -n 'git commit' f &&
echo '--no-verify'` блокировались (тот же класс, что исправлял ADR-026 для
merge). Секрет-скан запускался по подстроке `git commit` и не видел
`git -C dir commit` и `git -c k=v commit`.

Первые две версии этого ADR пытались угадать, как флаг дойдёт до `git`
через обёртки: склеивали слова за фразой, считали `xargs`/`parallel`
неоднозначностью, разбирали `$'…'`. Ревью (PR #269, круги 1–2) каждый раз
находило следующую форму (флаг в переменной, скрипт из stdin, `xargs echo |
sh`, `alias`, `$C`, `=git`), и код рос быстрее, чем закрывались формы.

## Решение

Тот же лексер, что у merge (ADR-026), один источник python-кода
(`ADK_INVOCATION_PY` в `lib/command-invocation.sh`, режим `git`), функция
`adk_command_git_bypass`: коды возврата как у `adk_command_invokes_pr_merge`
(0 — вызов или неоднозначность, 1 — нет, 2 — упоминание рядом с командой вне
белого списка), находки — в глобальной `ADK_GIT_FINDINGS` (`no-verify`,
`force-push`, `push-no-verify`, `ambiguous`, `commit`). Быстрый выход: в
тексте нет `commit` и `push`. Решение в три шага:

1. **Прямой вызов — по словам.** Простая команда со словом `git` (по
   basename или динамическим) в любом месте — так видны `env`, `sudo`,
   `xargs git commit …`, `eval git commit …`; перенаправления в слова не
   входят. Дальше глобальные опции из белого списка (`-C`, `-c`, `--git-dir`,
   `--work-tree`, `--namespace`, `--config-env`, `--super-prefix`; `-p`,
   `--no-pager`, `--bare` и прочие булевы), затем подкоманда. Найденная
   находка — отказ с прежним текстом.
2. **Инертность.** Все простые команды в тексте инертны — `inert()` из
   ADR-026 (`echo`, `grep`, `cat`, `git commit …`, `git log`, `gh pr`,
   `adk-log.sh`, `cd`, …) или `git push` в голове команды, чьи слова разобраны
   шагом 1 без находок, — упоминание в аргументах и heredoc не отказ (код 1).
3. **Иначе — один regex по всему тексту.** Есть неинертная команда
   (`bash`/`sh`/`eval`/`ssh`/`xargs`/`parallel`/`python`, присваивание,
   динамическое слово, неизвестная команда, `make`, …) либо сбой разбора
   (незакрытая кавычка, `$(` в unquoted heredoc, исключение) — проверяется
   текст целиком, линейно: фраза «слово `git`, слово `commit`/`push`» где
   угодно **и** токен обхода где угодно. Слово `git` — с любым префиксом
   (`=git` в zsh, `/usr/bin/git`, `"$(command -v git)"`), но не `.git` и не
   `git-`-часть чужого слова. `\xHH` и `\NNN` декодируются, остальные
   `\x` — пробел (`$'git\tcommit\t-n'`). Токены: для commit — `--no-verify`
   (и сокращения от `--no-v`), `-n` в любой склейке (`-an`, `-vn`, `-nm`);
   для push — `--no-verify`, `--mirror`, либо force-флаг (`-f` в любой
   склейке, `--force*`, `+ссылка` в том числе после кавычки) вместе со
   ссылкой `main`/`master` (в том числе `refs/heads/…`, `heads/…`; не
   `feat/main`, не `main-menu`), `--all`/`--branches` или `refs/heads/*`.
   Отказ — «не может отличить упоминание от вызова» (код 2, причина — по
   токену) либо «не может однозначно разобрать» (сбой разбора, код 0).

Шаг 3 по построению надмножество подстроки main: подстрока `git commit` и
`--no-verify` в одном тексте всегда попадают под фразу и токен. Поэтому
классы обходов, где флаг доходит до `git` не по словам вызова, закрыты без
правил на каждый: флаг в переменной (`F=--no-verify; bash -c "git commit $F"`),
скрипт из stdin (`bash -s -- --no-verify <<E`), `xargs echo … | sh`, `alias`,
`C='git commit'; $C --no-verify`, `"${cmd[@]}"`, `${=X}`, `=git commit`,
сбой разбора с `$F`.

**`git commit` по словам (шаг 1).** Блокируется `--no-verify` (в том числе
`--no-verify=…` и сокращения `--no-veri`, `--no-verif`: git их принимает) и
короткий `-n` в любой позиции и склейке. Склейка читается как у git: буква
значения (`m F C c t`) забирает остаток слова или следующее слово (`-mn` —
сообщение «n», `-m -n` — сообщение «-n», `-Fa -n` — флаг после значения),
`u` и `S` — только приклеенное значение. Значения длинных флагов
(`--message`, `--file`, `--author`, …) пропускаются так же. **`--`
заканчивает опции**: `git commit -m x -- -n` — путь `-n` (git отвергает его
как неизвестный pathspec, проверено на git 2.39). Позиционное слово вне `--`
с `$`, `{` в начале или подстановкой внутри — неоднозначность (`"$f"`,
`{-n,a}`, `$'\x2dn'`): оно может оказаться флагом; пути с переменными пишут
после `--`.

**`git push` по словам (шаг 1).** Блокируется принудительная запись в
`main`/`master`: `-f` (в склейке), `--force`, `--force-with-lease[=…]` и
сокращения от `--force-w`, либо `+`-ссылка. Цель — правая часть ссылки
(`<src>:<dst>`, без двоеточия — само слово) с нормализацией `refs/heads/` и
`heads/`; `main:feature` — не цель, ссылка со звёздочкой — цель. Принуждение
действует на ссылку, если оно глобальное или стоит `+` именно у неё
(`+feature main` разрешено). Remote — любой, все позиционные слова —
кандидаты в ссылки. `--all`/`--branches` с force и `--mirror` — запись во все
ветки. Динамическое слово среди позиционных и фигурные скобки в ссылке
(`{main,x}`) — неоднозначность: ссылка пишется литерально. Значение следующим
словом берут `-o`, `--repo`, `--receive-pack`, `--exec`, `--push-option`,
`--recurse-submodules`. `git push --no-verify` блокируется отдельным текстом:
`pre-push` — такой же гейт, как `pre-commit`; `-n` у push — `--dry-run`.

**Секрет-скан** (бывшая строка 97) — условие запуска **расширено, не
сужено**: подстрока `git commit` ИЛИ вызов `commit` по словам. Закрывает
`git -C d commit`, `git -c k=v commit`, `"$GIT" commit`; сужение отклонено
(`bash -c "git commit -m x"` остался бы без скана).

**Что не меняется.** Ветка merge (`deny_merge`, `check_merge_target`,
`ADK_PR_MERGE_TARGETS`), политика `policies.merge`, тексты отказов для
прямого `git commit --no-verify` и force push. Изменения поведения:
`git push -f origin main:feature` раньше блокировался подстрокой, теперь
разрешён (цель `feature`); `git push -f fork main`, `-f origin
refs/heads/main` раньше проходили, теперь блокируются.

## Отклонено

- **Дописать регулярки по словам вызова** (`-[a-z]*n`, `\+main`). Каждая
  форма — новая дыра, ложные срабатывания на упоминании остаются.
- **Угадывать, как флаг дойдёт до `git` через обёртку** (склейка слов за
  фразой, `xargs`/`parallel` как неоднозначность, разбор `$'…'`, ветка
  сбоя разбора по построчной фразе). Версии круга 1–2: ~100 строк кода, а
  ревью находило следующий обход. Шаг 3 — одна проверка по всему тексту.
- **Блокировать любое `git push --force*`.** `--force-with-lease origin
  <ветка>` — штатная форма `/work` после rebase.
- **Ограничить remote списком `origin|upstream`.** Список — whitelist
  обхода (`fork`, URL).
- **Второй лексер для git.** Один источник кода: правка лексера чинит и
  merge, и git.

## Последствия

- Штатные формы проходят (в том числе рядом друг с другом): `git commit -m
  "…"`, `-am`, `-F файл`, `git commit -m "$(cat <<'EOF' … EOF)"`, `git add
  … && git commit … && git push -u origin <ветка>`, `git push
  --force-with-lease origin <ветка>`, `git -C "$ROOT" commit`, `cd "$ROOT"
  && git commit`, `gh pr comment` и `adk-log.sh` с любыми фразами.
- Ложные отказы — только когда упоминание стоит в тексте рядом с неинертной
  командой (цена одной проверки по тексту; лечится разделением вызовов или
  `-F файл`): `grep "git commit" f | sort`; `ls docs/*.md | xargs grep -n
  "git commit"`; `make test && git commit -m "…-n…"`; `rm -rf build && git
  push origin main`; `git commit -m "… --no-verify …" && ./scripts/check`;
  `bash -c 'git commit -n …'`; `echo 'git commit -n' | bash`. Слово
  `commit`/`push` и токен считаются независимо от порядка и языка.
- Отказы шага 1 (литеральная запись снимает): `git push origin "$BRANCH"`,
  `git commit "$f"` (пути после `--`), `git push -f` с `$(…)` или `{…}`
  в ссылке.
- `echo $HOME $USER push` и `git --help commit` больше не дают ложный отказ
  (без токена обхода неинертная команда не мешает).
- Время линейно по длине команды (замеры в PR: ≤ 0.2 с на 100 КБ).
- Фикстуры (`tests/run.sh`, блок issue #265): таблица «команда => вид»,
  вид (allow / nv / force / pnv / amb / mention-*) сверяется по коду
  выхода и тексту причины, для allow — пустой stderr. Каждая подмена
  элемента (токен, склейка, значение, глобальная опция, оператор,
  инертность, проверка по тексту, сбой разбора) проверена мутацией на копии
  (отчёт в PR).

## Известные пропуски

Хук защищает от ошибок агента, а не от намеренного обхода; правил для этих
классов нет (ADR-026, «Известные пропуски»).

- **Токена обхода нет в тексте команды:** флаг приходит из файла или
  окружения (`bash -c 'git commit -m x $(cat fl)'` при `fl` с флагом,
  записанным другим вызовом, `xargs git commit -m x < flags.txt`), или
  собран из частей (`V=--no-; bash -c "git commit ${V}verify"`).
- **Фраза не видна:** `git comm""it -n`, `git pu""sh -f origin main`
  (быстрый выход и regex ищут литерал), `make commit` (цель Makefile).
- **Цель не названа в словах:** `git push --force`, `git push -f origin
  HEAD` при checkout main — цель берёт git из конфигурации и HEAD; в
  `commands/plan.md` `git push --force-with-lease` без ссылки — штатная форма.
- **Удаление и зеркало без force:** `git push --delete origin main`,
  `git push origin :main`.
- **Обход хуков не через флаг:** `git -c core.hooksPath=/dev/null commit`,
  `core.hooksPath` в конфиге; `--no-verify` у других подкоманд (`git merge`,
  `git rebase`, `git am`); псевдонимы git из конфига (`git ci -n`).
- **Глоб, раскрывающийся в файл `-n`:** `git commit ?n` при файле `-n`.
- **Запись файла, исполняемого другим вызовом** — класс из ADR-026.
