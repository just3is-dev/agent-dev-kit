# ADR-026: bash-guard определяет вызов `gh pr merge`, а не подстроку в тексте команды

Дата: 2026-10-10
Статус: accepted <!-- accepted | superseded by ADR-XXX -->

## Контекст

`bash-guard.sh` запускал проверку политики merge, если в тексте Bash-команды
встречалась подстрока `gh +pr +merge` (`grep -Eq`). Любое упоминание фразы —
`grep -n "gh pr merge" file`, `echo`, heredoc, `git commit -m`,
`gh pr comment --body`, `gh pr merge --help` — давало отказ, причём
вводящий в заблуждение («статус PR проверить не удалось» вместо «это не
вызов»). Код merge-пути (`commands/autopilot.md`, `adk-ralph.sh`, ADR-019,
ADR-025, тесты хука) сам описывает фразу, и поиск/правка по нему упирались
в хук (issue #260).

Обратная сторона той же подстроки: `gh -R o/r pr merge 5` под регулярку не
подпадал вовсе — вызов с флагом перед `pr` проходил хук без проверки.

## Решение

Хук вызывает `adk_command_invokes_pr_merge` (`hooks/scripts/lib/command-invocation.sh`).
Быстрый выход: в тексте нет слова `merge` — вызова нет, `python3` не
запускается. Иначе команда разбирается маленьким лексером (python3, уже
обязательная зависимость хуков, `json_field`) и проверяется по правилам.

**Лексер** понимает ровно то, что нужно, чтобы не принять текст за код и код
за текст: пробельные разделители, `;` `&&` `||` `|` `|&` `&` и перевод
строки, кавычки `'…'`, `"…"`, `$'…'`, экранирование `\`, комментарии `#`,
подстановки `$(…)`, обратные кавычки, `(…)`, `<(…)`/`>(…)`, heredoc
(`<<`, `<<-`, quoted и unquoted разделитель; here-string `<<<` — обычное
слово). Результат — единицы (список команд до `;`/`&&`/`||`/перевода
строки; всё вложенное — подстановки, подоболочки — разворачивается в
единицу внешней команды), у команды — слова с признаком «были кавычки».
Всё, чего лексер не понял (незакрытая кавычка или подстановка, heredoc без
терминатора, unquoted-heredoc с подстановкой внутри, исключение,
в том числе превышение рекурсии), — **не разбор, а вызов** (fail-closed):
если в сыром тексте есть слова `gh`, `pr`, `merge` в таком порядке.

**Вызов** — любое из:

1. *Прямой.* В одной простой команде есть слово `gh` (basename; либо
   динамическое — `$VAR`, `$(…)`), позже слово `pr`, позже слово `merge`.
   Это покрывает префиксы (`VAR=1`, `env`, `command`, `sudo`, `time`,
   `xargs`), `cd … &&` (отдельная единица), флаги `-R o/r` до и после `pr`,
   `$(…)` и обратные кавычки (их содержимое — команды той же единицы),
   `eval gh pr merge 5`. Единственное исключение — справка: слово
   `--help`/`-h`, не в кавычках, сразу после `merge`.
2. *Через строку.* Слово (аргумент в кавычках, тело heredoc) упоминает
   `gh … pr … merge` в одной строке, а в единице есть команда, не
   входящая в белый список «команда не исполняет свои аргументы»:
   `bash -c '…'`, `sh -c`, `eval "…"`, `ssh host "…"`, `python3 -c`,
   `echo "…" | bash`, `bash <<EOF`, `bash <(…)`, присваивание `X="…"`,
   `alias`. Белый список: `grep egrep fgrep rg echo printf cat head tail wc
   sort uniq cut tr tee nl`, скрипт `adk-log.sh`, `git` с подкомандой
   `commit tag log show notes diff grep status add stash branch` (до
   подкоманды допустим только `-C <путь>`), `gh pr|issue|api …`. Перед
   командным словом пропускаются `VAR=значение` и `if then elif else while
   until do ! {`.
3. *Записать и запустить.* Где-то в команде есть упоминание фразы (как в
   п. 2), а в другой единице стоит `bash sh zsh dash ksh source . eval exec`:
   `echo "gh pr merge 5" > run.sh && bash run.sh` раньше блокировался только
   потому, что подстрока была в тексте; правило сохраняет это.

Всё остальное — упоминание, не вызов.

**Что не меняется.** Политика (`policies.merge`), чтение статуса PR,
`adk_command_pr_number`/`adk_command_repo_flag` и тексты отказов — как были;
правка касается только условия «это вызов merge».

**Остальные подстрочные проверки** `bash-guard.sh` — `git commit` +
`--no-verify`, `git push --force … origin main`, секрет-скан на любое
упоминание `git commit` — **оставлены как есть**. Причины: (1) задача
про merge, у остальных своя цена ложного срабатывания — отказ требует
переформулировки только когда в одной команде есть обе подстроки, а
секрет-скан лишь лишняя работа; (2) для `--no-verify` и `--force` различитель —
флаг внутри вызова, а не само командное слово: нужен второй механизм
(слова вызова, а не только факт вызова), и он не нужен merge-проверке;
(3) в `git commit` секрет-скан безопаснее оставить fail-closed. Расширение
тем же лексером — отдельная задача.

## Отклонено

- **Вычёркивать кавычки регуляркой и искать подстроку в остатке.** Не
  переживает вложенность (`"$(cat <<'EOF' … EOF)"` — стандартная форма
  коммит-сообщения агента) и heredoc с апострофами в теле; не отличает
  `echo "…"` от `bash -c "…"`.
- **`shlex`.** Не знает heredoc, `$(…)` и перевод строки как разделитель:
  строка после `\n` склеилась бы с предыдущей командой — `echo ok⏎gh pr
  merge 5` читалось бы как аргументы `echo` (fail-open).
- **Чёрный список исполнителей (`bash -c`, `eval`, `xargs`, …).** Любой
  неучтённый (`ssh`, `python -c`, `watch`, `su -c`) — тихая дыра. Белый
  список «не исполняет аргументы» неполон в безопасную сторону: пропущенная
  команда даёт ложный отказ (как до этого ADR), а не пропуск merge.
- **Полный разбор bash (`bashlex` и т. п.).** Внешняя зависимость; хуки
  кита на встроенных средствах.

## Последствия

- Фразу можно искать и упоминать (`grep`, `echo`, heredoc, коммит-сообщение
  в форме `git commit -m "$(cat <<'EOF' … EOF)"`, комментарий PR,
  `adk-log.sh … reason="…"`) без обходных формулировок.
- `gh -R o/r pr merge 5`, `gh pr -R o/r merge 5`, `"gh" pr merge`,
  `gh pr \⏎merge 5`, `$GH pr merge` теперь блокируются (раньше проходили).
  Номер PR для запроса статуса `adk_command_pr_number` берёт по-прежнему
  из `gh pr merge <N>` в тексте; у `gh -R o/r pr merge 5` его нет — статус
  читается по ветке и обычно «unknown», отказ fail-closed. Улучшение
  разбора номера — отдельная задача.
- Остаются ложные отказы там, где команда не из белого списка получает
  фразу в аргументе (`find … -exec grep "gh pr merge" {} +`, `sed -n
  '/gh pr merge/p'`, `xargs grep`, `timeout 5 grep`) и где слова `gh pr
  merge` идут отдельными словами без кавычек (`echo gh pr merge`).
  Формулировка остаётся прежней: квотировать фразу и звать `grep`/`echo`.
- Остаются пропуски, которые подстрока тоже не ловила: фраза, собранная
  из частей (`mer""ge` в обход быстрого выхода, `g=gh; $g …` ловится только
  как динамическое слово), содержимое файла, написанного в одном вызове и
  исполненного в другом, `gh api -X PUT …/merge`. Хук — ремень от
  случайности и очевидных обходов, не песочница; у человеческого merge
  второй рубеж — серверный (branch protection).
- Фикстуры `tests/run.sh` (issue #260) закрепляют обе стороны; состояние PR
  в «не блокируются» — `draft`, поэтому возврат к подстроке краснит их.
