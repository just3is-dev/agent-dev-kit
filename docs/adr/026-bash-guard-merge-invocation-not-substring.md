# ADR-026: bash-guard определяет вызов `gh pr merge`, а не подстроку в тексте команды

Дата: 2026-10-10
Статус: accepted <!-- accepted | superseded by ADR-XXX -->

## Контекст

`bash-guard.sh` запускал проверку политики merge, если в тексте Bash-команды
встречалась подстрока `gh +pr +merge` (`grep -Eq`). Любое упоминание фразы —
`grep -n "gh pr merge" file`, `echo`, heredoc, `git commit -m`,
`gh pr comment --body`, `gh pr merge --help` — давало отказ, причём
вводящий в заблуждение («статус PR проверить не удалось» вместо «это не
вызов»). Код merge-пути (`commands/autopilot.md`, `adk-ralph.sh`, ADR-019,
ADR-025, тесты хука) сам описывает фразу, и поиск/правка по нему упирались
в хук (issue #260).

Обратная сторона той же подстроки: `gh -R o/r pr merge 5` под регулярку не
подпадал вовсе — вызов с флагом перед `pr` проходил хук без проверки.

Подстрока при этом была грубой, но неприступной: любой способ исполнить
строку с фразой (`bash -c`, запись в файл и запуск, `printf -v X …; $X`,
`GIT_EDITOR='…' git commit`) она ловила, потому что не разбирала команду.
Всякий разбор — это обещание «эту часть текста не исполнят», и каждое такое
обещание должно быть проверено на «исполняется ли оно».

## Решение

Хук вызывает `adk_command_invokes_pr_merge` (`hooks/scripts/lib/command-invocation.sh`).
Быстрый выход: в тексте нет слова `merge` — вызова нет, `python3` не
запускается. Иначе команда (через stdin, чтобы не упираться в `ARG_MAX`)
разбирается небольшим лексером на `python3` (уже обязательная зависимость
хуков, `json_field`).

**Лексер** даёт плоский список простых команд, каждая — список слов:
разделители `;` `&&` `||` `|` `|&` `&`, перевод строки; кавычки `'…'`,
`"…"`, `$'…'`, экранирование `\`, комментарии `#`; `$(…)`, обратные
кавычки, `(…)`, `<(…)`/`>(…)` (их содержимое — такие же команды, слово
снаружи получает неразличимую метку подстановки); heredoc (`<<`, `<<-`,
разделитель в кавычках и без; тело — слово команды-владельца; here-string
`<<<` — обычное слово). Всё, чего лексер не понял — незакрытая кавычка
или подстановка, heredoc без терминатора, unquoted-heredoc с `$(`/обратными
кавычками в теле, любое исключение (в том числе превышение рекурсии), —
**не разбор, а вызов** (fail-closed), если в сыром тексте слова `gh`, `pr`,
`merge` идут в таком порядке.

**Вызов** — любое из:

1. *Прямой.* В одной простой команде слово `gh` (по basename; либо
   динамическое слово — `$VAR`, `$(…)`), позже слово `pr`, позже слово
   `merge`. Это покрывает префиксы (`VAR=1`, `env`, `command`, `sudo`,
   `time`, `xargs`), `cd … &&`, флаги `-R o/r` до и после `pr`, `$(…)` и
   обратные кавычки, `eval gh pr merge 5`. Единственное исключение —
   справка: слово `--help`/`-h` сразу после `merge`.
2. *Упоминание и неинертная команда.* Какое-то слово (аргумент, тело
   heredoc) упоминает `gh … pr … merge` в одной строке, и в команде, где
   угодно, есть простая команда, не входящая в белый список. Исполнение
   строки (`bash -c`, `eval "…"`, `ssh`, `python -c`, `| bash`, `bash <<EOF`),
   запись в файл и запуск (`> run.sh && chmod +x run.sh && ./run.sh`,
   `env bash run.sh`, `make`, `python3 m.py`), голое динамическое слово
   (`printf -v X '…'; $X`, `${=X}`, `$(<f)`, `$(cat f)`), присваивание
   (`GIT_EDITOR='…' git commit`) — всё это неинертные команды: у них
   командное слово не из списка. Решение принимается по всей команде, а не
   по её части: часть `grep "…" f && ./scripts/check` тоже блокируется.
3. *Запись и запуск через инструмент.* Упоминание есть, все команды из
   белого списка, но в команде есть запись в файл (`>`, `>>`, `&>`,
   `tee`) и команда второго яруса — `git` или `adk-log.sh`: они исполняют
   код из файлов (хуки git, `core.hooksPath`, `.gitattributes`, сам скрипт).

**Белый список** — команды, которые не исполняют свои аргументы и не имеют
опции, запускающей программу. Ярус 1: `grep egrep fgrep echo printf cat head
tail wc cut tr uniq nl tee cd ls pwd` (голым именем, без пути) и
`gh pr|issue|api …`. Ярус 2: `git` с подкомандой `commit tag log show notes
diff status add stash branch` (до подкоманды допустим только `-C <путь>`) и
`adk-log.sh` (по basename). Приставки `VAR=значение`, `env`, `sudo`,
ключевые слова оболочки (`if`, `for`, `do`, …) в белый список не входят:
команда с ними неинертна. Сознательно вне списка: `rg --pre`, `sort
--compress-program`, `git grep -O/--open-files-in-pager` — у них есть опции,
исполняющие аргумент.

**Что не меняется.** Политика (`policies.merge`), чтение статуса PR,
`adk_command_pr_number`/`adk_command_repo_flag` и тексты отказов — как были;
правка касается только условия «это вызов merge». Побочный эффект
fail-closed: если `python3` недоступен или упал, хелпер возвращает «вызов»,
и команда со словом `merge` без фразы получает тот же текст отказа (в
хуке уже на стадии `json_field` без `python3` команда читается пустой —
это прежнее поведение, не часть решения).

**Остальные подстрочные проверки** `bash-guard.sh` — `git commit` +
`--no-verify`, `git push --force … origin main`, секрет-скан на любое
упоминание `git commit` — **оставлены как есть**. Причины: (1) задача
про merge, у остальных своя цена ложного срабатывания — отказ требует
переформулировки только когда в одной команде есть обе подстроки, а
секрет-скан лишь лишняя работа; (2) для `--no-verify` и `--force` различитель —
флаг внутри вызова, а не само командное слово: нужен второй механизм
(слова вызова, а не только факт вызова), и он не нужен merge-проверке;
(3) в `git commit` секрет-скан безопаснее оставить fail-closed. Расширение
тем же лексером — отдельная задача.

## Отклонено

- **Вычёркивать кавычки регуляркой и искать подстроку в остатке.** Не
  переживает вложенность (`"$(cat <<'EOF' … EOF)"` — стандартная форма
  коммит-сообщения агента) и heredoc с апострофами в теле; не отличает
  `echo "…"` от `bash -c "…"`.
- **`shlex`.** Не знает heredoc, `$(…)` и перевод строки как разделитель:
  строка после `\n` склеилась бы с предыдущей командой — `echo ok⏎gh pr
  merge 5` читалось бы как аргументы `echo` (fail-open).
- **Чёрный список исполнителей (`bash -c`, `eval`, `xargs`, …).** Любой
  неучтённый (`ssh`, `python -c`, `watch`, `su -c`) — тихая дыра.
- **Решение «по единицам» (упоминание блокирует только свою цепочку
  `;`/`&&`) и отдельный список запускателей файла (`bash`, `sh`, `.`).** Первая
  версия этого ADR так и делала; ревью показало обходы: `chmod +x run.sh &&
  ./run.sh`, `env bash run.sh`, `make`, `python3 m.py`, `$(cat f)`. Любой
  неучтённый запускатель — дыра, а общее правило «упоминание + любая
  неинертная команда в команде» проще и не имеет списка запускателей.
- **Полный разбор bash (`bashlex` и т. п.).** Внешняя зависимость; хуки
  кита на встроенных средствах.

## Последствия

- Белый список неполон в сторону ложных отказов, но не пропусков **при
  условии**, что у каждой команды списка нет опции, исполняющей аргумент;
  это условие проверено для перечисленных команд и нарушено у `rg`, `sort`,
  `git grep` — потому они вне списка. Новая команда в списке требует той же
  проверки.
- Фразу можно искать и упоминать одиночной командой (`grep`, `echo`,
  heredoc, `cat > f <<EOF`, коммит-сообщение, в том числе в форме
  `git commit -m "$(cat <<'EOF' … EOF)"`, комментарий PR,
  `adk-log.sh … reason="…"`) без обходных формулировок.
- Составные команды, где упоминание соседствует с любой командой вне
  списка, блокируются: `grep "…" f && ./scripts/check`,
  `git commit -m "…" && git push`, `grep "…" f | sort`, `for f in …; do
  grep "…" $f; done`, `git grep "…"`, `X=1 grep "…"`. Выход — разделить на
  вызовы или квотировать и вынести проверку отдельно; это цена
  отсутствия списка запускателей.
- `gh -R o/r pr merge 5`, `gh pr -R o/r merge 5`, `"gh" pr merge`,
  `gh pr \⏎merge 5`, `$GH pr merge` теперь блокируются (раньше проходили).
  Номер PR для запроса статуса `adk_command_pr_number` берёт по-прежнему
  из `gh pr merge <N>` в тексте; у `gh -R o/r pr merge 5` его нет — статус
  читается по ветке и обычно «unknown», отказ fail-closed. Улучшение
  разбора номера — отдельная задача.
- Остаются пропуски, которые подстрока тоже не ловила: быстрый выход по
  слову `merge` не видит `gh pr m''erge`, `gh pr {merge,}`; фраза,
  собранная из частей (`g=gh; $g …` ловится только как динамическое слово);
  содержимое файла, записанного в одном вызове и исполненного в другом
  (в одной команде — блокируется); `gh api -X PUT …/merge`. Хук — ремень
  от случайности и очевидных обходов, не песочница; серверный рубеж
  (branch protection) остаётся отдельным.
- Фикстуры `tests/run.sh` (issue #260) закрепляют обе стороны; состояние PR
  в «не блокируются» — `draft`, поэтому возврат к подстроке краснит их.
  Каждое правило и каждая ветка fail-closed лексера имеют фикстуру
  «блокируется», проверенную мутацией на копии.
