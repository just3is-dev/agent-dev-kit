# ADR-004: валидация заголовка PR — PostToolUse по состоянию, не PreToolUse по команде

Дата: 2026-08-14
Статус: accepted <!-- accepted | superseded by ADR-XXX -->

## Контекст

SPEC-002 (AC-5): при `conventions.commitStyle=conventional` заголовок PR
(будущее сообщение squash-коммита в main) обязан соответствовать
`<commitType>[(scope)]: <суть> (#N)`. Первая реализация (PR #62, круги
ревью 1–3) валидировала текст Bash-команды в PreToolUse-хуке bash-guard:
извлекала `--title` из `gh pr create/edit` разбором shell. Три круга
ревью подряд находили пары «ложный запрет / молчаливый пропуск» одного
класса: непарные кавычки, кавычка через перевод строки, heredoc,
продолжения `\`, shell-подстановки (`$VAR`, `$(...)`). Каждый фикс
парсера порождал зеркальную дыру: корректная проверка требует почти
полного shell-лексера, а его отсутствие фейлит гейт в обе стороны.

## Решение

Сменить слой: PostToolUse-хук `pr-title-check.sh` (matcher Bash) после
команды, упоминающей `gh pr create/edit`, читает **фактический**
заголовок PR (`gh pr view --json number,title`) и валидирует его.
Нарушение → exit 2: действие уже случилось, поэтому это не блок, а
требование агенту исправить заголовок через `gh pr edit`; после
исправления хук молчит (петля сходится за один шаг).

Что это даёт по построению:
- текст команды не разбирается вовсе — класс ошибок shell-лексера
  исчезает целиком (подстановки, кавычки, heredoc безразличны);
- ложный триггер фильтра (упоминание `gh pr create` в heredoc/доке)
  безвреден: проверяется реальный PR — корректен или отсутствует → тишина;
- проверка строже прежней: любой `gh pr edit` сверяет заголовок, даже
  если сама команда его не меняла.

Отклонённые альтернативы:
- третья итерация PreToolUse-парсера (снятие heredoc + разбор с
  некавыченным `\n` как разделителем) — реализуемо, но хвост краевых
  случаев остаётся, а цена ошибки — блок легальной команды;
- только серверный линтер (`externalTitleLint`) — требует настройки CI
  в каждом проекте, локальная петля обратной связи быстрее и дешевле;
- сузить проверку до литеральных однострочных `--title` — молча
  пропускает доминирующие формы из `commands/work.md`.

Цена решения: проверка не превентивна (PR мгновение живёт с плохим
заголовком до исправления) и требует сети (`gh pr view`); недоступность
gh/PR — fail-open, как и раньше для labels issue.

Область действия относительно «Границ» SPEC-002 («валидация — для новых
PR»): хук сверяет любой PR, которого коснулась команда, — в том числе
созданный до включения `conventional` и отредактированный после. Это
осознанный выбор, «Границы» переформулированы под него: массового
переписывания старых PR не требуется (нетронутые PR хук не видит), но
правка старого PR приводит его заголовок к конвенции — иначе история
main после squash останется смешанной.

## Последствия

- bash-guard больше не знает о заголовках PR; вся логика конвенции — в
  `hooks/scripts/pr-title-check.sh` (карта `types.*` дублируется теперь
  там, тесты поведения — AC-5 в `tests/run.sh`).
- Общий контекст команды (git toplevel по кандидатам, `-R/--repo`, номер
  PR) вынесен в `lib/paths.sh` (`adk_command_git_root`,
  `adk_command_repo_flag`, `adk_command_pr_number`) и используется обоими
  хуками — по ADR-002 («общее — в lib»). Сетевые вызовы `gh pr view`
  остаются инлайн в каждом хуке: поля и фолбэки различаются
  (isDraft/reviewDecision против number/title), общий хелпер был бы
  параметризованной обёрткой ради двух вызовов.
- Опечатка в значении `conventions.commitStyle` не блокирует: enum-читатель
  вернёт дефолт `plain` с предупреждением в stderr, хук промолчит.
  В отличие от `policies.merge` (fail-closed) гейт заголовков
  информирующий, а не merge-критичный — молчание не открывает опасное
  действие (зафиксировано в docs/config.md).
- Тестовые обходы сети: `ADK_GUARD_PR_TITLE` (фактический заголовок,
  `unavailable` = gh недоступен), `ADK_GUARD_ISSUE_LABELS` (как раньше).
- Issue #47 и AC-5 SPEC-002 переформулированы под новый слой
  (постановка изменена с одобрения владельца после трёх кругов ревью).
