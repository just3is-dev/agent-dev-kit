# ADR-021: `/work` не берёт issue, пока файл его спеки не в main

Дата: 2026-09-30
Статус: accepted <!-- accepted | superseded by ADR-XXX -->

## Контекст

ADR-009 заставляет `/plan` мержить PR спеки финальным шагом (после
создания issues вехи), через тот же хук `bash-guard.sh`, что и любой
`gh pr merge`. При `policies.merge=agent-after-approve` (дефолт) это
проходит внутри одного прогона `/plan`. При `human-review-required` или
`human-only` хук отказывает агенту: PR спеки остаётся ready, а issues
вехи (с аннотациями `AC-N (ждёт #M)`) уже созданы и видны в GitHub. `/work`
может взять такой issue немедленно — но шаг 3 предписывает снять
аннотацию «ждёт #N» в том же PR, где появился тест, а файла спеки в
`main` ещё нет: снимать аннотацию не с чего (issue #218).

Это не гипотетическое окно: пресет «командный» (`docs/config.md`) держит
`policies.autopilot.enabled=true` вместе с `policies.merge=
human-review-required` — `/autopilot` и `hooks/scripts/adk-ralph.sh` в
этой конфигурации штатно продолжают выбирать задачи, пока PR спеки ждёт
человека.

## Решение

`/work` шаг 1 читает из тела issue литеральную строку `Спека:
docs/specs/NNN-<слаг>.md` (её пишет `/plan` шаг 4 — формат теперь
зафиксирован текстом, не только «ссылкой» смыслом) и проверяет файл в
`main` (`git cat-file -e origin/main:<путь>`). Файла нет — issue не
берётся: при авто-выборе пропускается тем же способом, что незакрытая
«Blocked by #N»; номер задан явно — остановка с объяснением пользователю.
`/autopilot` шаг 1 получает симметричную проверку в своей собственной
(текстовой) логике выбора задачи — без неё оркестратор передал бы такой
issue субагенту, тот остановился бы без ветки и PR, а шаг 3 `/autopilot`
(судит по фактам `gh`: PR нет) ошибочно пометил бы это как застревание
(`needs-human`, уведомление) вместо легального ожидания человека.

`hooks/scripts/adk-ralph.sh` **не меняется в этой задаче**: его
Python-селектор (`select_next`) — отдельный, тяжело тестируемый механизм
(десятки фикстур в `tests/run.sh`, каскады SKIP/blocked-on-ready) со
своей историей ADR (ADR-007, ADR-014, ADR-019). Корректный фикс требует
такого же нового класса исключения, как `owner:human`/`Blocked by #N`
(парсинг ссылки на спеку, git-проверка файла в `origin/main`, новые
фикстуры), — объём, не умещающийся в атомарную задачу (skills/decompose:
~300 строк диффа). Отложено отдельным issue (см. отчёт PR issue #218).

Отклонённые альтернативы:
- **Вариант (а) issue #218** — `/work` при отсутствии файла спеки в main
  сам правит её в ветке спеки. Отклонено пользователем: решение принято
  до реализации как вариант (б), не предмет выбора агента.
- **Вариант (в) issue #218** — переносить снятие аннотации на первый PR
  после merge спеки, с механической проверкой (issue #200 смежен).
  Отклонено: не устраняет саму гонку — issue вехи всё равно можно начать
  раньше, чем спека в main, просто аннотация снимется позже; вариант (б)
  устраняет гонку в корне, не давая issue стартовать вовсе.
- Останавливать `adk-ralph.sh` этим же PR — отклонено по объёму
  (см. «Решение» выше); альтернатива — принять временный риск ложного
  `needs-human` в пресете «командный» до отдельного фикса.

## Последствия

- Формат ссылки на спеку в теле issue — теперь часть контракта, а не
  просто «для человека»: `/plan` обязан писать её литерально, `/work` и
  `/autopilot` — парсить. Issue, созданный не через `/plan` (вручную, без
  строки «Спека:»), проверке не подлежит — она не может звонить в
  пустоту.
- Проверка read-only и дешёвая (`git fetch` + `git cat-file -e`) — не
  требует изменений в `hooks/scripts/adk-config.sh` или конфиге проекта.
- `adk-ralph.sh` в пресете «командный» до отдельного фикса может редко
  ошибочно пометить такой issue `needs-human`, если возьмёт его раньше
  merge спеки человеком, — известный, принятый временный риск, не
  регрессия (сегодня, до ADR-021, `/work`-часть той же гонки вообще не
  имела контракта).
