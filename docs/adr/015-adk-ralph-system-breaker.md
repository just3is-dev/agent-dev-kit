# ADR-015: adk-ralph.sh — breaker уровня системы (красные гейты main, отказ журнала, серия конфликтов актуализации)

Дата: 2026-09-27
Статус: accepted <!-- accepted | superseded by ADR-XXX -->

## Контекст

SPEC-003 «Стадийный circuit breaker» описывает три уровня реакции.
Уровень «Задача» и «Прогон» — отдельные задачи плана (issues #130-134),
вне рамок этой. Уровень «Система» (issue #135, половина AC-5, вторая
половина — уровень прогона, issue #134) требует немедленного полного
стопа на трёх независимых сигналах: красные контрактные гейты (`scripts/check`,
`scripts/test`) на main до старта итерации; отказ записи в журнал
(`adk-log.sh`); серия подряд идущих git-конфликтов при актуализации.

Три неочевидных решения нужно зафиксировать:

1. Как отличить «в проекте нет `scripts/check`/`scripts/test`»
   (переходное состояние, не ошибка — docs/contract.md допускает проект без
   контракта) от «скрипт есть, но упал» (красный гейт, стоп)?
2. Как отличить обычный, ожидаемый на всех текущих ralph-фикстурах отказ
   `git pull` (нет `origin` — фикстуры создаются голым `git init`, без
   remote) от настоящего git-конфликта слияния при актуализации default
   branch, и как считать «серию подряд идущих»?
3. Журнал (`adk-log.sh`) в `commands/*.md` — не гейт: `|| true` там
   осознанный дизайн (проваленная запись не блокирует задачу). В
   `adk-ralph.sh` этот же вызов теперь обязан останавливать прогон. Как
   провести эту границу, не трогая семантику журнала в командах?

## Решение

1. **Наличие скрипта — через `-x` самого файла, не через код возврата
   попытки его запустить.** `run_main_gates()` (новая функция
   `hooks/scripts/adk-ralph.sh`) проверяет `[ -x "$root/scripts/check" ]`
   и `[ -x "$root/scripts/test" ]` независимо друг от друга — тот же
   приём, что уже используют все хуки кита (`hooks/scripts/stop-test.sh`:
   `[ -x "$proj/scripts/test" ] || exit 0`). `command -v` сюда не подходит:
   контрактные скрипты вызываются по относительному пути от корня проекта
   (docs/contract.md), а не через PATH — `command -v scripts/check` не
   резолвит относительный путь так, как ожидается, и вносит путаницу с
   поиском бинарей. Отсутствие скрипта — тихий пропуск (return 0), скрипт
   есть и вернул ненулевой код — красный гейт (return 1, вывод скрипта в
   stderr для диагностики). Гейт вызывается первой инструкцией на каждой
   итерации внешнего цикла (до `select_next`) — красные гейты запрещают
   итерацию, даже если она свелась бы к одному `SKIP` без единого вызова
   `claude`.
   - Отклонённая альтернатива: требовать оба скрипта вместе (упасть, если
     есть один, но не другой). Отклонено — DoD явно требует штатного
     прохождения проекта вовсе без контракта, а частичный контракт
     (например, только `scripts/check` в процессе миграции стека) не
     назван issue как ошибочное состояние; трактуем его так же
     великодушно, как хуки кита.

2. **Счётчик + фиксированный порог 2, отличение конфликта от «нет
   origin» через `MERGE_HEAD`.** `return_to_default_branch()` теперь зовёт
   `git pull --no-rebase` (стратегия зафиксирована явно — иначе поведение
   зависит от ambient `pull.rebase` вызывающего окружения/CI, и признак
   конфликта ниже перестаёт быть надёжным: rebase-конфликт не создаёт
   `MERGE_HEAD`). Если `git pull --no-rebase` вернул ненулевой код,
   решающий факт — `git rev-parse -q --verify MERGE_HEAD`: существует →
   это настоящий конфликт слияния (git начал слияние и застрял на
   пересекающихся правках), а не сбой без слияния (нет `origin`, сеть
   недоступна, репозиторий без единого коммита). Только настоящий конфликт
   увеличивает `actualization_conflict_streak`; любой другой исход
   (успех или сбой без `MERGE_HEAD`) сбрасывает счётчик в 0. При конфликте
   слияние сразу прерывается (`git merge --abort`), чтобы не оставить
   дерево в `merge-in-progress` следующей итерации. Порог — `2`, зашит в
   коде, не вынесен в `adk.config.json`: в отличие от `maxStuckPerRun`/
   `maxSkippedShare` (уровень прогона, issue #134 — тюнинг политики
   проекта), системный breaker — безусловная защита инфраструктуры
   прогона, её порог не место для проектного тюнинга. `2` — тот же
   консервативный дефолт, что у `maxStuckPerRun` (SPEC-003).
   - Отклонённая альтернатива: считать любой ненулевой код `git pull`
     конфликтом. Отклонено — сломало бы все существующие ralph-фикстуры
     (`git init` без единого `remote`, `git pull` в них уже сегодня
     проваливается на каждой итерации молча, `|| true`); без различения
     через `MERGE_HEAD` системный breaker срабатывал бы на каждом прогоне
     без ни одного настоящего конфликта.
   - Известный предел решения: без git identity (`user.name`/
     `user.email`) в репозитории `git pull --no-rebase` отказывает
     командой `git commit` до начала слияния ("Committer identity
     unknown"), `MERGE_HEAD` не появляется вовсе — настоящий конфликт
     неотличим от отсутствия identity, счётчик серии не растёт. Фикстура
     `tests/run.sh` явно выставляет `user.name`/`user.email` в
     клонированном репозитории, а не полагается на глобальный git-конфиг
     машины/CI (на CI без него тест первоначально падал).

3. **Отдельная функция `journal_break()` только для `adk-ralph.sh`.**
   Оборачивает установку `stop_reason`/`exit_code` при отказе `"$logger"
   ...` (ненулевой код `adk-log.sh`). Каждый вызов `"$logger" ... || true`
   внутри цикла и запись `event=run_start` до цикла заменены на `if !
   "$logger" ...; then journal_break; <возврат дерева, если уже был
   claude -p>; break; fi`. Финальная запись `event=run_end` в общем хвосте
   скрипта остаётся `|| true`: к этому моменту цикл уже завершился (по
   любой причине), останавливать больше нечего, а сама сводка/уведомление
   не зависят от успеха этой последней записи. `commands/*.md`
   (`/work`, `/autopilot`, `/review`) не тронуты — их `"|| true"` остаётся
   осознанным дизайном («журнал — наблюдаемость, не гейт» для одной
   задачи); граница проведена ровно по файлу `adk-ralph.sh`, где журнал —
   часть системных предохранителей прогона, а не отчётности по задаче.

## Последствия

- `run_main_gates()`, `journal_break()` — новые функции только в
  `hooks/scripts/adk-ralph.sh`; ни одна не переиспользуется командами.
- `return_to_default_branch()` теперь вызывает `git pull --no-rebase`
  вместо `git pull` — наблюдаемое отличие только при конфликте (раньше
  молча проглатывался как best-effort, теперь считается и может
  остановить прогон после `actualization_conflict_threshold` конфликтов
  подряд); на успехе или обычном сбое без `origin` поведение не меняется.
- Три новых значения `event=run_end.reason` в `autopilot-<дата>.jsonl`:
  `"системный breaker: красные гейты main"`, `"системный breaker: отказ
  записи журнала"`, `"системный breaker: серия конфликтов актуализации"`
  — аддитивное расширение ADR-001 «Расширения схемы»; реестр ADR-007 §3
  обновлён синхронно (оба места правятся вместе, как и раньше — расхождение
  между ними уже случалось, круг 2 ревью PR #141).
- Breaker уровня прогона (issue #134, вторая половина AC-5:
  `maxStuckPerRun`, `maxSkippedShare`) и остальные задачи плана (#129-133,
  #138) не затронуты — работают поверх этой версии без изменений.
