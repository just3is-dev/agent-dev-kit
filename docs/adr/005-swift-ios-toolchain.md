# ADR-005: swift-ios — линт/формат только тулчейном Xcode, версия Xcode в CI не фиксируется

Дата: 2026-08-15
Статус: accepted <!-- accepted | superseded by ADR-XXX -->

## Контекст

Шаблон `templates/swift-ios/` (issue #70) требует линтер и форматтер для
контрактного `scripts/check|fix` и работающий macOS-CI. Экосистемные
кандидаты — SwiftLint и SwiftFormat — внешние установки (brew) с
собственными версиями и конфигами: их пришлось бы ставить и в CI, и на
каждую машину разработчика, а расхождение версий даёт расхождение
вердиктов гейта. Отдельно: первый прогон CI на опорном проекте
(baby-tracker) упал при фиксации версии Xcode через `xcode-select` —
на образах GitHub рантаймы симуляторов установлены только для Xcode
по умолчанию, переключение на другую версию оставило сборку без
iOS-рантайма (`Unable to find a destination…`).

## Решение

1. Линт и формат — только `swift format` из состава тулчейна Xcode 16+
   (`lint --strict`, иначе нарушения не роняют гейт): ноль внешних
   установок, локально и в CI одна версия тулчейна. На Xcode 15 и старше
   сабкоманды `format` нет — требование 16+ названо в README и
   project-init. Конфиг шаблона переопределяет единственный дефолт:
   `indentation.spaces = 4` (дефолтные 2 переформатировали бы любой
   экосистемный проект целиком при первом же `fix`); всё остальное —
   дефолты тулчейна (lineLength 100 и т.д.), в конфиг не дублируются.
2. Версия Xcode в CI не фиксируется: используется дефолт образа
   (`macos-15`), фактическая версия печатается в лог
   (`xcodebuild -version`).

## Последствия

- Плюс: контракт работает «из коробки» на любой машине с Xcode 16+ и на
  голом раннере; нет дрейфа версий линтера.
- Минус: правила `swift format` беднее SwiftLint; проект с потребностью
  в строгих кастомных правилах добавит их сам поверх контракта.
- Минус: тулчейн CI может разъехаться с локальным (опорный случай:
  CI 16.4 при локальных 16.2) — расхождение видно по логу версии и по
  вердиктам swift-format; фиксация версии осознанно отвергнута как
  ломающая симуляторные рантаймы.
