# ADR — записи архитектурных решений

ADR — то, что человек будет читать вместо кода, чтобы понять «почему так».
Пишутся в `docs/adr/NNN-<слаг>.md` по шаблону
`${CLAUDE_PLUGIN_ROOT}/templates/process/adr-template.md`.

## Когда писать

- Выбор между реальными альтернативами (библиотека, хранилище, протокол,
  архитектурный паттерн), где «почему» не восстановить из кода.
- Отступление от дефолта проекта или привычной практики.
- Решение, которое дорого развернуть назад.

## Когда НЕ писать

- Очевидный выбор без альтернатив.
- Пересказ того, что видно из кода.
- Решения уровня «как назвать переменную».

Сомневаешься — не пиши. Лишние ADR обесценивают нужные.

## Правила

- Одна страница максимум. Контекст → решение → последствия.
- Самодостаточность: читается без других документов и истории чата.
- ADR не редактируют задним числом: решение изменилось — новый ADR со
  ссылкой «supersedes ADR-NNN», старому статус superseded.
- Номер — следующий по порядку в `docs/adr/`.
