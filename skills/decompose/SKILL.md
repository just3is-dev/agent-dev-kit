# Декомпозиция на атомарные задачи

Автономный агент, делающий «большую фичу» одним заходом, гарантированно
производит мусор. Единица работы — атомарная задача.

## Критерии атомарности

Задача обязана удовлетворять всем пунктам:

1. **Один PR, читаемый за 10 минут.** Ориентир — до ~300 строк диффа без
   учёта тестов и lock-файлов. Больше — режь дальше.
2. **Самодостаточная формулировка.** Исполнитель может взять задачу, не читая
   переписку: контекст, что сделать, definition of done — внутри задачи.
3. **Проверяемый результат.** У задачи есть критерий «сделано», выражаемый
   тестом или наблюдаемым поведением. «Отрефакторить X» без критерия — не задача.
4. **Минимум зависимостей.** Зависимости между задачами указываются явно
   («после #N»). Граф зависимостей — цепочка или дерево, не паутина.
5. **Работающая система после каждой задачи.** Любой промежуточный merge
   оставляет проект зелёным. Нельзя планировать «сломаем в #3, починим в #5».

## Формат задачи

```
### <номер>. <глагол + результат>
Контекст: <зачем это в рамках спеки, 1–2 предложения>
Сделать: <что именно, где, границы>
DoD: <проверяемые условия завершения; какие тесты это доказывают>
Зависит от: <номера задач или «—»>
```

## Анти-паттерны

- Задача «сделать всё остальное» в конце плана.
- Задача-исследование без артефакта (результат ресёрча — ADR или уточнение спеки).
- Горизонтальная нарезка «весь бэкенд» / «весь фронтенд» для фичи, которую
  можно нарезать вертикально (сквозной кусочек поведения за задачу).
- Инфраструктурные задачи «на будущее», не требуемые критериями приёмки спеки.
