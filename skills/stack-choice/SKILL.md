# Выбор стека под задачу

Дефолты: фронт — Next.js, бэк — NestJS, мобилки — React Native. Отступать
от дефолта можно и нужно, когда задача объективно лучше решается другим
инструментом (пример: ML/данные → Python-микросервис).

## Правила выбора

1. **Задача важнее привычки.** Критерии: зрелость экосистемы для этой задачи,
   объём кода, который придётся написать самим, наличие готовых шаблонов
   контракта в agent-dev-kit.
2. **Отступление от дефолта = ADR.** Одна страница: почему дефолт хуже,
   что выбрали, чем платим (см. скилл adr).
3. **Новый сервис — отдельная единица со своим контрактом**, а не «папка
   рядом»: своя реализация scripts/check|test|fix (шаблоны:
   `${CLAUDE_PLUGIN_ROOT}/templates/`), покрытие в CI.

## Обязательство контракта

Железное правило: **код вне контракта = непроверяемый код = его не существует.**
Добавил язык/сервис — в том же PR расширь scripts/check, scripts/test и CI,
чтобы новый код проходил через те же гейты. PR, добавляющий код мимо гейтов,
не подлежит merge независимо от качества самого кода.
